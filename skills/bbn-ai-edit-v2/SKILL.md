# BBN AI EDIT V2

สกิลตัดต่อเฉพาะคลิป Long ของ BoomBigNose โดยใช้ **EP228 Edit2 Long v3** เป็นตัวอย่างที่ผู้ใช้รับรองเมื่อ 6 ตุลาคม 2026 ใช้หน้าจอและผู้พูดจริง แทรกเนื้อหาให้ตรงกับสิ่งที่อธิบาย และเปลี่ยนเลย์เอาท์ด้วยแอนิเมชันเฉพาะช่วงที่ช่วยให้เข้าใจ

ตามการรวม flow ที่ผู้ใช้กำหนดเมื่อ 8 ตุลาคม 2026 ใช้ [bbn-ai-edit](../bbn-ai-edit/SKILL.md) เป็นจุดเริ่มงานหลักและใช้สกิลนี้สำหรับ Long เท่านั้น เรียก `$bbn-ai-edit-v2 ตัด EP…` โดยตรงให้ทำเฉพาะ Long; ถ้าผู้ใช้ขอครบชุดหรือระบุ Short, Skool, Package หรือปกด้วย ให้ใช้ flow ของ bbn-ai-edit สำหรับงานเหล่านั้น อ่านกฎร่วมและการส่งงานจาก bbn-ai-edit โดยไม่เริ่ม intake ใหม่หรือเรียก Long ซ้ำ คำสั่งล่าสุดของผู้ใช้มีลำดับความสำคัญสูงสุด

- ใช้ transcript, sync, cut plan, assets และ QA เดิมที่ยังใช้ได้ ถอดเสียงฟุตเทจที่ไม่เปลี่ยนเพียงครั้งเดียว ตรวจจังหวะคำเฉพาะจุดที่ไม่แน่ใจ
- เก็บงาน Edit2 ใน `<EP>/edit2/` พร้อมไฟล์วิดีโอ แผนตัดต่อ composition ที่แก้ไขได้ และ `VERIFY.md` เก็บรุ่นก่อนเมื่อแก้ไข
- รักษาฟุตเทจต้นฉบับและชุด Long/Short ที่มีอยู่ งานแก้ Long เฉพาะส่วนไม่เปลี่ยนเลย์เอาท์ที่รับรองแล้วนอกขอบเขตคำขอ การเปลี่ยนภาพเฉพาะส่วนต้องรักษาเสียง จังหวะตัด ความยาว และ Timeline ที่รับรองแล้ว
- ใช้งบ EP สะสมเดียวรวมงานแก้ไข เป้าหมายไม่เกิน 10 percentage points ของโควตา Codex รายสัปดาห์ ตามงบสะสม EP เดิมใน bbn-ai-edit ต้องทราบฐานคำนวณก่อนงานหนัก แยกโควตาบัญชีรวมออกจากการใช้ที่ระบุให้ EP ได้ ห้ามอ้างว่า enforce เพดานได้เมื่อไม่มีการวัดที่เชื่อถือได้

## 2. ตัดคำพูดและหน้าจอด้วยแผนเดียวกัน

รักษาคำทักทาย ประโยคเปิด–ปิดที่ครบ และขั้นตอนสาธิตที่มีความหมาย ตัดช่วงเงียบ การลองผิดที่ซ้ำ และคำพูดสั่งคนตัดต่อ พร้อมตัดภาพการค้นหา/รอ/ลองใหม่ที่ตรงกัน หากพูดผิดแล้วแก้ทันที ให้ใช้คำแก้ที่ครบถ้วน

### ตัดคำซ้ำและพูดใหม่ให้หมดก่อนประกอบ (เจ้าของช่อง 2026-10-25, EP248)

EP248 v2 ยังเหลือคำซ้ำที่เจ้าของช่องต้องชี้เอง 5 จุด เช่น "ให้ AI ช่วยคิด แล้วให้ AI ช่วยคิด", "เข้าใจเข้าใจ", "ก่อนเริ่มก่อนเริ่ม", พูดประโยคเดิมสองรอบโดยมี "อ่ะ" คั่น และพูดตัวเลขผิดแล้วแก้ ("ได้สองร้อยยี่สิบ ได้ร้อยยี่สิบ") Long ต้องไม่ส่งไปทั้งที่ยังมีแบบนี้

- ห้ามใช้ Whisper segment หาคำซ้ำ เพราะ Whisper รวมหรือข้ามคำที่พูดซ้ำ ให้ใช้ข้อความ Qwen ทั้งเรื่องแล้วรัน `python3 scripts/find_repeats.py asr/qwen_windows.json` (สกิลนี้) จะได้รายการเวลาโดยประมาณของวลีที่ถูกพูดซ้ำติดกัน และคำ filler (เอ่อ / อ่ะ / เอ้ย / ไม่ใช่นะครับ)
- ไล่ดูทุกรายการ บางรายการเป็นการพูดปกติ เช่น "Claude Code" ที่ ASR อ่านเป็น "โค้ดโค้ด", "หมัดชนหมัด" หรือการขยายความแบบ "อีพีหน้า อีพีถัดไป" ส่วนที่เป็นการพูดซ้ำ พูดใหม่ หรือพูดผิดแล้วแก้ ให้ตัด
- **เก็บรอบหลังที่พูดครบและชัด** ตัดรอบแรก รวมคำคั่นอย่าง "แล้ว" หรือ "อ่ะ" ที่อยู่ระหว่างสองรอบ ถ้าพูดผิดแล้วแก้ ให้เก็บคำที่แก้แล้ว
- หาจุดตัดจาก ASR ช่วงสั้น (Qwen 1–3 วินาที) ร่วมกับจุดเงียบของ RMS (ช่วงละ 20–40 ms) ตัดที่จุดเงียบ ห้ามใช้เวลาคำของ Whisper เป็นขอบตัด เพราะคลาดได้ราว 0.3 วินาที (EP248 เหลือ "อ่ะ" สั้นๆ ที่รอยต่อเพราะเหตุนี้) แล้วทดสอบรอยต่อด้วย ASR บนเสียงที่ต่อแล้วทุกจุด รอยต่อต้องอ่านเป็นประโยคเดียวที่ไม่มีคำซ้ำ ไม่มีพยางค์ขาด
- หลัง encode ให้ถอดเสียงไฟล์ Long จริงอีกรอบ รัน `find_repeats.py` ซ้ำ ต้องเหลือแค่รายการที่ตัดสินแล้วว่าเป็นการพูดปกติ บันทึกจำนวนที่พบ ที่ตัด และที่เก็บไว้ (พร้อมเหตุผล) ใน `VERIFY.md`

กล้อง หน้าจอ และเสียงต้องใช้ frame cut และ sync เดียวกัน บันทึกช่วงที่ตัด เหตุผล และหลักฐาน แล้ว remap กราฟิก โมชัน เสียงประกอบ และ chapters ผ่านแผนตัดต่อเดียวกัน ตรวจไม่ให้ตัดพยางค์หรือทำให้ผู้ชมพลาดผลลัพธ์

## 3. พื้นหลังและเลย์เอาท์หลัก

ใช้ [พื้นหลังที่ผู้ใช้ให้ในชุดติดตั้งนี้](../bbn-ai-edit/assets/shared/background/background-supplied.png) เป็นพื้นหลังจริง ขยายแบบ cover โดยรักษาสัดส่วนและสีเดิม ดู [provenance](../bbn-ai-edit/assets/shared/background/SOURCE.md); `bg.webp` ในเอกสารนำเข้าเป็นไฟล์บนเครื่องเดิม ไม่ใช่พาธ runtime บนเครื่องปลายทาง

- **เนื้อหา/หน้าจอจริงอยู่ซ้าย** ในกรอบแนวนอนขนาดใหญ่ มุมมน
- **ผู้พูดจริงอยู่ขวา** ในกรอบสี่เหลี่ยมสูง มุมมน วางกึ่งกลางแนวตั้งอยู่นอกหน้าจอ
- รักษาสัดส่วนหน้าจอเดิม และ crop ผู้พูดให้เห็นศีรษะครบโดยไม่ยืดใบหน้า ใช้ crop คงที่ที่เหมาะกับฟุตเทจของช่วงนั้นเป็นหลัก ให้ผู้พูดขยับตัวตามธรรมชาติได้ ไม่ติดตามหน้าทุกเฟรมหรือดึงหน้ากลับกลางตลอดคลิป เพราะทำให้ภาพส่ายและเวียนหัว ปรับ crop เฉพาะเมื่อศีรษะกำลังชนขอบหรือหลุดเฟรม โดยเลื่อนเท่าที่จำเป็นอย่างนุ่มนวลแล้วค้างตำแหน่งใหม่ ไม่ไล่ตามการขยับเล็กน้อยและไม่แกว่งกลับไปมา ตรวจเฉพาะช่วงเสี่ยงและขอบเขตการปรับจากเฟรมจริง พร้อมบันทึกเวลา หากใบหน้าออกจากภาพต้นฉบับ ห้ามสร้างส่วนที่หาย; ช่วงเคลื่อนไหวสั้นที่ไม่ใช่ขั้นตอนสอนอาจค้างภาพกล้องจริงเฟรมสุดท้ายที่ครบ โดยรักษาหน้าจอ เสียงและความยาวเดิม พร้อมบันทึกช่วงที่ใช้
- วางคำอธิบายในพื้นที่ว่างของพื้นหลังเมื่อการวางทับหน้าจอจะบังปุ่มหรือข้อมูลสำคัญ

ค่าตัวอย่าง EP228 บน canvas 1920×1080:

| รูปแบบ | หน้าจอ | ผู้พูด |
|---|---|---|
| หลัก | x24, y117, 1504×846, radius28 | x1556, y240, 340×600, radius32 |
| หน้าจอใหญ่ขณะสอน | ขยายหน้าจอโดยเก็บข้อมูลสำคัญครบ | ต้องมีผู้พูดให้เห็น ศีรษะไม่หลุดกรอบและไม่บังปุ่มสำคัญ |
| หน้าจอใหญ่ + ผู้พูดเล็ก | x24, y108, 1696×954 | x1624, y576, 272×480 |
| ผู้พูดเต็ม | หน้าจอจางออก | กล้องจริงเต็ม canvas ตามสัดส่วน |

ตัวเลขเป็นจุดเริ่มต้นจาก EP228 ปรับ crop และตำแหน่งให้เหมาะกับฟุตเทจของแต่ละ EP โดยตรวจปุ่มที่กล่าวถึงจริง ภาพตัวอย่าง Nate และภาพ `2.png`–`6.png` ใช้อ้างอิงการจัดวางเท่านั้น ห้ามนำคน แบรนด์ หรือกล่อง placeholder จากตัวอย่างมาใส่ในงานจริง

## 4. แอนิเมชันเปลี่ยนเลย์เอาท์

เปิดด้วย teaser จากช็อตจริงในตอนที่เห็นผลลัพธ์หรือประโยชน์ชัดและน้ำเสียงมีพลัง เลือกสีหน้าและจังหวะที่น่าติดตาม ไม่ใช้ช่วงลังเล ผิดหวัง หรืออธิบายข้อบกพร่องเป็นภาพเปิดโดยค่าเริ่มต้น ทำ montage สั้นเมื่อช่วยให้เห็นผลงาน โดยรักษาประโยคจริงที่ครบและความสัมพันธ์กับภาพ ไม่สร้างคำพูดใหม่ ตรวจต้นคลิปที่ encode แล้วทั้งภาพและเสียงก่อนส่ง จากนั้นใช้ผู้พูดใหญ่และค่อยย่อเข้ากรอบขวาขณะเผยหน้าจอ ใช้เลย์เอาท์หลักเป็นส่วนใหญ่ของช่วงสอน ปิดด้วยผู้พูดใหญ่เพื่อกล่าวลา

เมื่อขยายหน้าจอหลักระหว่างสอน ต้องคงผู้พูดไว้ในกรอบที่เหมาะสม ห้ามซ่อนหรือจางผู้พูดออกเพียงเพราะขยายหน้าจอ เลือกหน้าจอใหญ่พร้อมผู้พูดเล็กขวาล่างในช่วงอธิบายที่พื้นที่นั้นไม่บังข้อมูล แอนิเมชันต้องสัมพันธ์กับเนื้อหาและไม่ย้ายผู้พูดทุกครั้งที่เปลี่ยนภาพ แต่ภาพต้องมีชีวิต: ช่วงอธิบายใช้โมชันของ bbn-explainer-motion ให้มีการเคลื่อนต่อเนื่อง และช่วงสอนใช้ zoom/pan เข้าจุดที่คลิกหรือพูดถึงบนหน้าจอจริงบ่อยขึ้น (ผู้ใช้ขอเพิ่มโมชัน 2026-10-21) ฉากโมชันเต็มเฟรมให้ใช้เลย์เอาท์ "หน้าจอใหญ่ + ผู้พูดเล็ก" เพื่อให้กราฟิกใหญ่ เหมือนคลิปอ้างอิงที่ผู้พูดอยู่กรอบเล็กขวาล่าง

ใช้ HyperFrames/GSAP ที่ seek ตามเวลาได้อย่างแน่นอน เคลื่อนและเปลี่ยนขนาดอย่างต่อเนื่อง รักษาสัดส่วน และค้างภาพให้อ่านทัน ช่วงเปลี่ยนเลย์เอาท์ของ EP228 ใช้ประมาณ 0.65–0.8 วินาทีเป็นตัวอย่าง ปรับตามจังหวะพูด ตรวจภาพเริ่ม กลาง จบ และทั้งสองขอบเขตของการเปลี่ยน

ห้ามเปลี่ยนไปภาพผู้พูดหรือ insert จนผู้ชมพลาดการคลิก ป้อนค่า เมนู โค้ด หรือผลลัพธ์ที่กำลังสอน

## 5. โมชันอธิบายและการแทรกเนื้อหา

งาน Long ใหม่ให้ใช้ [bbn-explainer-motion](../bbn-explainer-motion/SKILL.md) เสริมเฉพาะช่วงอธิบายแนวคิด แบ่ง explanation/teaching จากคำพูดและภาพจริงก่อนวาง cue; จบโมชั่นและป็อปอัพก่อนเฟรมเริ่มสอน ใช้หน้าจอจริงในเลย์เอาต์ V2 ตลอดช่วงสาธิต รวมช่วงรอโหลดและอธิบายขั้นตอนในสาธิต ไม่เพิ่มโมชั่นของสกิลนี้มาบังช่วงสอน ใช้เสียง/clock/cut plan เดิม และไม่เริ่มแก้คลิปที่รับรองแล้วจากการติดตั้งสกิลเพียงอย่างเดียว

**Long ไม่ใส่ subtitle ถอดคำพูดทั้งประโยค และไม่ใส่ข้อความคำเน้นสีเหลืองด้านบนจอ** (ยกเลิกคำเน้นเหลือง `#ffe500` แบบ EP228–EP242 ตามผู้ใช้ 2026-10-21 รวม teaser) ใช้โมชันอธิบายของ bbn-explainer-motion แทน ข้อความสั้นที่อยู่ในกราฟิกโมชันเป็นส่วนของฉาก ไม่ใช่แถบข้อความด้านบน กฎนี้ใช้เฉพาะ Long; Short ใช้กฎซับและข้อความของ bbn-ai-edit

- สคริปต์ตัวอย่างที่มี `keywords` ใน manifest หรือ `.kw` ใน `gen_index.py` ให้เว้นว่าง/ไม่ render สำหรับ Long
- การเน้นบนหน้าจอจริงระหว่างสอนใช้ zoom/pan กรอบหรือไฮไลต์สีส้มของ explainer ไม่ใช้ข้อความหรือไฮไลต์สีเหลือง

แทรก prompt แผนภาพ ข้อความอ้างอิง ภาพเปรียบเทียบ หรือผลลัพธ์ที่ตรงกับคำอธิบาย ใช้หน้าจอที่บันทึกไว้ก่อน จะ crop/zoom หรือเน้นบางบริเวณได้โดยเก็บบริบทให้เข้าใจ แล้วกลับหน้าจอสาธิตก่อนขั้นตอนถัดไป

เมื่อจำเป็นต้องใช้เว็บประกอบ ให้ตรวจหน้า official ก่อน capture ใช้หน้า public ไม่ login หรือส่งฟอร์ม ระบุ domain และแยกให้ชัดว่าเป็นภาพประกอบ ไม่ใช่หน้าจอที่ผู้พูดบันทึก เก็บ URL วันที่ capture ไฟล์/hash หัวข้อ และช่วงเวลาใน `footage-ledger.json` ห้ามสร้าง UI ปลอมทดแทนการสาธิตที่ขาด ถ้าผู้พูดอธิบายการทำบนจอแต่ไม่มีภาพ ให้อัดหน้าจอจริงด้วย `screencapture -v` ทำตามขั้นตอนที่พูด ตัดให้ตรงจังหวะเสียง เบลอข้อมูลส่วนตัว และบันทึกลง ledger เดียวกัน

## 6. เสียง CTA และข้อมูลส่วนตัว

**ห้ามใส่ประโยคชวนคอมเมนต์ใต้คลิปใน Long (ผู้ใช้ 2026-10-21):** ตัดประโยคแบบ "พิมพ์ ... ใต้คอมเมนต์ แล้วผมส่ง...ให้" หรือ "คอมเมนต์ด้านล่างแล้วไปลุยกันเลย" ออกจาก Long ทุกครั้ง แม้เป็น pickup ที่อัดแยกมาให้ ใช้ประโยคแบบนี้ได้เฉพาะ Short/โพสต์โซเชียล CTA ของ Long คือ like/share/subscribe เท่านั้น

เพิ่ม SFX คลิ๊กเบา ๆ เฉพาะจังหวะคลิ๊ก เปลี่ยนหน้า หรือ transition ที่มีความหมาย เลือกบางจังหวะให้มีลูกเล่นและเว้นช่วง ไม่ใส่ทุกคลิ๊กหรือทุกการเปลี่ยนภาพ ซิงก์เสียงกับการกระทำที่เห็นจริง ไม่กลบคำพูด และตรวจเสียงในไฟล์ encode รวมรอยต่อและหางเอฟเฟกต์

Long ใส่เพลงประกอบเบา ๆ ที่ได้ยินจริงใน teaser/ช่วงเปิดเป็นค่าเริ่มต้น ใช้เพลงเดิมที่ผู้ใช้เลือก เช่น Do It ที่ความเร็วเดิม มี fade เข้า/ออก อยู่ใต้เสียงพูด และหยุดก่อนเข้าสอน ไม่ใส่เพลงต่อเนื่องในช่วงเนื้อหาโดยค่าเริ่มต้น ใช้ voice/music/SFX stems และวัดเป้าหมายประมาณ −16 LUFS, true peak ไม่เกิน −1 dBTP ในไฟล์จริง การแก้ teaser ต้องรักษาหรือใส่เพลงช่วงเปิดกลับด้วย ไม่ถือว่า stem ที่วัดได้แต่ฟังไม่ออกผ่านการตรวจ การแก้เฉพาะภาพรักษา mastered audio ที่รับรองแล้วทั้งสตรีม

เมื่อเปิดคลิปตัวอย่าง ให้เก็บ stem เสียงกล้องแยกจากเสียง digital ของคลิปตัวอย่าง ห้าม mute เสียงกล้องทั้งช่วงโดยอาศัย VAD อย่างเดียว เพราะเสียงพูดเบาอาจถูกจัดว่าไม่มี narration ตรวจ ASR/waveform เฉพาะช่วงและ encoded output ก่อนลดเสียง ใช้การ duck เสียงตัวอย่างใต้เสียงพูด และปรับระดับเสียงกล้องเฉพาะช่วงที่ขอ ไม่เร่งทั้ง master รวมเพลง/ตัวอย่างพร้อมกัน

เพิ่มเสียงติ๊กถูก/ติ๊งสั้น ๆ เฉพาะบางจังหวะยืนยันหรือแสดงผลลัพธ์จริง เป็นเสียงอย่างเดียว ไม่เพิ่มภาพติ๊กถูกหรือกราฟิก เว้นระยะ ไม่ซ้อนกับเสียงคลิกหรือใส่ทุกขั้นตอน ลดระดับให้ไม่กลบคำพูดและเก็บหางเสียงครบ ตรวจช่วงที่แก้จากไฟล์ encode จริงและระบุการฟังแบบ real time ตามที่ทำได้จริง ค่าเริ่มต้นเพลงเปิดและเสียงติ๊งนี้ตามผู้ใช้ 2026-10-07

CTA like/share/subscribe ใช้ animation ที่ให้มา วางกึ่งกลางแนวนอนในส่วนล่างของภาพให้พ้นใบหน้าผู้พูด ตรงช่วงเชิญชวน รักษาเสียงและ entrance/click/exit เดิม กำจัด green spill ช่วงท้ายให้ผู้พูดจอใหญ่เต็ม canvas ไม่ย่อหรือย้ายไปกรอบขวา ตรวจใบหน้ากับ CTA ทุกช่วง entrance/hold/click/exit และปรับตำแหน่งหรือขนาดเฉพาะ animation เมื่อจำเป็น ค่าเริ่มต้นนี้ตามผู้ใช้ 2026-10-07 แทนการวางกลางภาพทับผู้พูดของ 2026-10-06

ข้อมูลส่วนตัวที่อ่านได้ให้ blur เฉพาะตำแหน่งและติดตามเมื่อเลื่อน/ย้ายหน้าต่าง ถอน blur เมื่อข้อมูลออกจากภาพ รักษา URL สาธารณะและปุ่มที่จำเป็น รหัสผ่านที่แสดงเป็น bullets อยู่แล้วไม่ต้องปิดทับเป็นแถบใหญ่

### CTA preflight เมื่อใช้ renderer เดิม

ก่อน render Long ให้ตรวจคำสั่งและ asset ที่ renderer ใช้จริง: CTA ต้องอ้างอิงคลิป animation ที่ให้มา และ map เสียง native ของ asset เข้า final mix ไม่ใช่ PNG หรือข้อความแทน การที่ไฟล์ final มี audio stream ไม่ได้พิสูจน์ว่ามีเสียง CTA ตรวจ entrance/click/exit จากภาพ encode และยืนยันเสียงเอฟเฟกต์จาก encoded mix เทียบ stem เดิม หากเสียงถูกตรวจด้วย waveform/correlation ให้ระบุว่าไม่ใช่การฟัง real time

เมื่อ speech cut เปลี่ยนตำแหน่ง AAC frame ให้ตรวจ true peak ของไฟล์ encode ใหม่ แม้ใช้ mastered stem เดิม เพราะการ re-encode อาจเกิด peak เพิ่ม หากต้องแก้ ใช้ peak-only safety processing และ mux กับภาพเดิม ไม่ normalize ทั้งเรื่องหรือ render ภาพซ้ำโดยไม่จำเป็น แยกหลักฐานว่า source mix ถูก remap ตรงจากคำอ้างว่า final PCM ไม่เปลี่ยน

## 7. ส่งต่อ flow ที่ไม่ใช่ Long

Short, Skool, Package และปกใช้ [bbn-ai-edit](../bbn-ai-edit/SKILL.md) และ specialist ที่สกิลนั้นกำหนดทั้งหมด ไม่ใช้กฎเลย์เอาท์หรือค่าเริ่มต้นไม่ใส่ซับของ V2 กับ Short และไม่เก็บกฎ Package/Skool ซ้ำในสกิลนี้

เมื่อเป็นงานครบชุด หลัง Long ผ่าน QA และส่งรีวิวแล้วให้ดำเนินงานที่เหลือต่อใน bbn-ai-edit ตามลำดับ **Long → Package → ปก → Short** รวม Skool เมื่อผู้ใช้ขอ โดยใช้ manifest transcript cut plan assets และงบสะสม EP เดิม ไม่เริ่มงาน Long ซ้ำ งานแก้ Long เฉพาะภาพที่ความยาวไม่เปลี่ยนไม่เริ่มทำ Package ปก Short หรือ Skool ใหม่ และต้องรักษา Package ที่ผู้ใช้แก้บน Drive ล่าสุด

## 8. ตรวจและส่งงาน

ก่อน encode ทั้งคลิป ตรวจชุดรีวิวจริง: เปิดคลิป รอยต่อที่เปลี่ยน โมชัน/insert (ไม่มีข้อความเหลืองด้านบน) CTA ผู้พูดกับปุ่มสำคัญ เสียงประกอบ ตอนจบ และภาพต้นฉบับเทียบ output ที่เวลาเดียวกัน แก้จุดผิดก่อน render

หลัง encode ตรวจ frame count เวลาและ sync รอยต่อ/พยางค์ ความชัดของหน้าจอ ขนาดตัวอักษร/ไอคอนเล็กสุดของโมชันตามเกณฑ์ใน bbn-explainer-motion blur และ loudness/true peak ในไฟล์จริง แอนิเมชันต้องตรวจภาพช่วงกลางและภาพที่หยุดค้าง ไม่ถือว่า HTML preview หรือ decode ผ่านอย่างเดียวเป็น QA ภาพผ่าน

การแก้เฉพาะบางช่วงใช้ encoded streams เดิมได้เมื่อ codec configuration ตรงกันและต่อที่ขอบเขต stream ที่ปลอดภัย ตรวจไฟล์ที่ประกอบแล้ว รวมทุก audio packet/timestamp เมื่ออ้างว่าเสียงเหมือนเดิม หยุด QA เมื่อเช็กที่เกี่ยวข้องผ่าน ไม่ render ใหม่เพียงเพราะอัปโหลดมีปัญหา

บันทึก `VERIFY.md` ว่าตรวจอะไร ใช้หลักฐานเดิมอะไร มีข้อจำกัดอะไร และได้ฟังแบบ real time หรือไม่ อย่าอ้างการฟังที่ไม่ได้ทำ

ส่งไป Drive/Telegram ผ่านเส้นทางที่ผู้ใช้อนุญาตไว้เท่านั้น ตรวจขนาด/hash ของไฟล์บน Drive จริงก่อนแจ้งรีวิว งานแก้อัปทับไฟล์เดิมชื่อเดิมด้วย `../bbn-ai-edit/scripts/drive_replace.sh` ให้ file ID/link เดิมและ md5 ตรง เก็บรุ่นก่อนใน `archive/` ในเครื่อง ห้ามอัปไฟล์ชื่อมีเวอร์ชันหรือซ้ำ ไม่แทน source หรือไฟล์ที่ไม่ใช่ของงานนี้ การตัดและส่งรีวิวไม่รวมสิทธิ์ publish บน YouTube/โซเชียล
