# BBN AI Edit — สรุปสกิลและมาตรฐานงาน

ปรับปรุงตามคำสั่งผู้ใช้ถึง 28 กันยายน 2026

เอกสารนี้รวมขั้นตอนและข้อกำหนดล่าสุดสำหรับงาน BBN ในไฟล์เดียว เป็นสรุปสำหรับอ้างอิง ไม่ได้ติดตั้งโมเดล โปรแกรม หรือระบบอัตโนมัติด้วยตัวเอง คำสั่งล่าสุดของผู้ใช้และ AGENTS.md ของโปรเจกต์มีลำดับเหนือค่าเริ่มต้นในสกิลย่อย

## 1. ขอบเขตและสกิลที่ใช้

งานครบชุดประกอบด้วย Long, Short, ชื่อคลิป, แคปชัน, Description, Timeline, Tags และปก ใช้ข้อมูลตอนเดียวกันร่วมกันทั้งหมด หากผู้ใช้สั่งแก้เฉพาะจุด ให้แก้เฉพาะขอบเขตนั้น ไม่เริ่มงานทั้งหมดใหม่

| สกิล | หน้าที่ |
|---|---|
| bbn-ai-edit | ประสานงานทั้งตอนและส่งงาน |
| bbn-ai-cut | ตัด Long/Short จังหวะพูด ภาพ เสียง ซับ และตรวจคุณภาพ |
| bbn-youtube-tags | ค้นคำเกี่ยวข้องครั้งเดียวและจัด Tags |

สกิลหลักที่ติดตั้ง: `~/.codex/skills/bbn-ai-edit/SKILL.md` และสกิลย่อยอยู่ใต้ `~/.codex/skills/` อ่านเฉพาะส่วนที่เกี่ยวกับงานปัจจุบัน

## 2. ลำดับทำและส่งงาน

**Long → YouTube Package → ปก → Short**

1. ทำ Long และตรวจไฟล์จริงก่อน แล้วอัปขึ้น Drive ส่งลิงก์ให้ตรวจทันที
2. ทำ Package จากเนื้อหาและเวลาของ Long ฉบับส่งจริง แล้วอัปทันที
3. ทำปกตามจำนวนที่กำหนด ปกใดตรวจผ่านแล้วส่งได้เลย ไม่รอทุกแบบ
4. ทำ Short จากเนื้อหาที่ตรวจแล้ว ให้สอดคล้องกับ Long และแคปชัน

ไม่รอครบชุดก่อนส่ง Preview/ไฟล์ตรวจ ระหว่างผู้ใช้ตรวจ ให้ทำส่วนที่เหลือต่อภายในขอบเขตที่อนุญาต รับข้อแก้เข้ามารวมในแผนล่าสุด งานทั้งตอนเสร็จก็ต่อเมื่อส่งครบสิ่งที่ขอ

เมื่อแก้ไฟล์ ให้แทนที่ไฟล์งานเดิมบน Drive โดยคง ID และลิงก์ เก็บเวอร์ชันก่อนหน้าไว้ในเครื่อง ห้ามเขียนทับต้นฉบับหรือไฟล์ของงานอื่น หาก Drive ยังประมวลผลวิดีโอ ให้แจ้งสถานะจริง ไม่อ้างว่าเปิด Preview ได้แล้วจากการอัปโหลดสำเร็จเพียงอย่างเดียว

## 3. การประหยัดเวลาและโทเคน

- เป้าหมายไม่เกิน **15% ต่อ EP รวม Long, Short, Package, ปก, retries และทุกรอบแก้** ไม่เริ่มนับใหม่เมื่อเปลี่ยนเซสชัน
- ต้องทราบก่อนว่า 15% อ้างถึงโควตาหรืองบใด ปัจจุบันยังไม่ได้ระบุฐานคำนวณ ห้ามรับรองว่า enforce เพดานได้หากยังวัดไม่ได้ และห้ามแปลงจำนวน tokens เป็นเปอร์เซ็นต์เอง
- เก็บบันทึกงบสะสมต่อ EP แยกการใช้งานบัญชีร่วมออกจากการใช้ที่ระบุได้ว่าเป็นของ EP นี้ เผื่องบสำหรับรอบแก้
- เมื่อใกล้เพดาน ส่งสิ่งที่ตรวจแล้วและแจ้งงานที่เหลือก่อนใช้โมเดลเพิ่มอย่างมีนัยสำคัญ
- หนึ่ง EP ใช้ผู้ทำงานตัดต่อหลักคนเดียว ไม่เปิดงานซ้ำที่แก้ไฟล์ร่วมกัน
- ถอดเสียงต้นฉบับที่ไม่เปลี่ยนเพียงครั้งเดียว ใช้ transcript, alignment, assets, stems, renders และ QA เดิมร่วมกัน
- ใช้ ASR ตัวที่สองหรือ CTC เฉพาะช่วงไม่แน่ใจ รวมข้อแก้ทั้งหมดก่อนเรนเดอร์
- Patch ช่วงที่เปลี่ยนเมื่อทำได้อย่างปลอดภัย ไม่เรนเดอร์ทั้งคลิปเพื่อแก้จุดเล็กโดยไม่จำเป็น
- ให้เครื่องมือในเครื่องจัดการ render/upload/wait และเก็บ log ไม่เรียกโมเดลซ้ำเพื่อบรรยายการรอ
- ตรวจผ่านแล้วส่ง ไม่วนตรวจหรือสร้างตัวเลือกนอกคำขอ การอัปโหลดค้างไม่ใช่เหตุให้ตัดหรือเรนเดอร์ใหม่
- ห้ามประหยัดด้วยการข้ามการตรวจประโยค ความคมชัด ซิงก์ และข้อมูลลับ

## 5. มาตรฐานการตัด Long

### เนื้อหาและจังหวะ

- ตัด dead air คำฟิลเลอร์ที่เกินจำเป็น คำซ้ำ และเทคที่พูดแก้ โดยไม่ทำให้พยางค์หรือประโยคขาด
- เมื่ออธิบายซ้ำหรือออกเสียงผิดแล้วแก้ทันที ให้ตัดครั้งแรกและเก็บประโยคแก้ที่สมบูรณ์ ตรวจว่าไม่มีข้อมูลจำเป็นหาย
- คำสั่งที่พูดถึงคนตัด เช่น “เอาตรงที่เลื่อนหาออกเลยนะ” ต้องตัดทั้งคำสั่งและช่วงค้นหา/รอที่เกี่ยวข้อง กลับมาต่อที่ทำสำเร็จแล้ว
- ใช้ cut plan เดียวกันกับภาพจอ กล้องและเสียง ตรวจคำอธิบายตรงกับภาพจริง เช่น พูดถึงสามคลิปต้องเห็นสามคลิป
- เปิดด้วยประโยคที่สมบูรณ์และผลลัพธ์จริง ไม่ใช้ภาพไม่ตรงคำพูดหรือเสียงซ้อน เลือกจังหวะหน้าอินโทร/โชว์ผลงานตาม brief

### หน้าผู้พูดและกราฟิก

- จัดใบหน้าจริงให้อยู่กลาง crop รักษาสัดส่วน สีผิวและฉากห้องเดิม
- ตำแหน่งหน้าคงที่เมื่อไม่บังเนื้อหา ย้ายเฉพาะช่วงที่บังปุ่ม/ข้อความที่กำลังอธิบาย ตรวจทั้งก่อนและหลังการย้าย
- กล่องคำอธิบายอยู่ขวาบน เว้นขอบเล็กน้อย เช่น y=36 ที่ 1080p เป็นค่าตั้งต้น ไม่ใช่การรับประกันว่าไม่บัง
- ข้อความขาว เน้นคำสำคัญเหลือง ไม่ขีดเส้นใต้โดยอัตโนมัติ พื้นรองข้อความ Long ใช้ opacity 25% เมื่อใช้ตามสไตล์ช่อง
- ขึ้นข้อความเมื่อเริ่มพูดหัวข้อนั้น ค้างจนจบความหมาย แล้วค่อยออก ไม่กำหนดหายหลัง 5 วินาทีโดยไม่ดูเสียง
- CTA กดไลก์/แชร์/ติดตาม เป็นข้อยกเว้น: อยู่กลาง ใหญ่และเด่น ตรงกับคำชวน รักษาแอนิเมชันและเสียงเดิม ไม่บังหน้าและไม่มีขอบเขียว

### เสียงและช่วงโปรโมต

- ใช้เสียงพูดหลักชุดเดียวที่ซิงก์แล้ว ไม่ให้กล้องและจอพูดทับกัน ลดเสียงแทรก กระแอม และรอยต่อที่สะดุด
- เพลงและ SFX ไม่กลบคำพูด ตรวจเสียงจากไฟล์ส่งจริง
- ช่วง Skool BoomBigNose+: ใช้โลโก้จริงกลางภาพเด่นชัด เริ่มเพลงที่ทำนองหลัก ไม่เริ่มจากอินโทรเงียบยาว
- กระดิ่ง/เสียงเน้นหลังโลโก้ปรากฏดังพอเหมาะ เพลงเบาใต้เสียงพูดและจบไม่นานหลังประโยคโปรโมต ไม่ลากเข้าช่วงสอน

### ข้อมูลลับ

เบลอเฉพาะ access token, channel secret, API/client secret ที่เห็นรหัสครบและอ่านได้ ปิดเฉพาะตัวรหัส ไม่ครอบหัวข้อหรือทั้งเว็บไซต์ ไม่ปิด URL สาธารณะ ช่องที่ซ่อนไว้แล้วหรือรหัสที่เห็นไม่ครบเพียงเพราะมีชื่อ key ตรวจขอบเวลาแบบรายเฟรมเพื่อไม่ให้รหัสหลุดหนึ่งเฟรม ห้ามพิมพ์รหัสจริงลง log หรือข้อความส่งงาน

## 6. มาตรฐาน Short

- แนวตั้ง 9:16 โดยทั่วไปประมาณ 30–60 วินาที ปรับให้ประโยคและสาระสมบูรณ์
- **จอเนื้อหาครึ่งบน ผู้พูดครึ่งล่าง ตั้งแต่เฟรมแรก** จัดหน้าให้อยู่กลางและปรับจอให้เนื้อหาที่อธิบายเห็นครบ
- มีประโยคเปิด ไม่เริ่มกลางคำหรือกลางความคิด และจบกระชับเพื่อชวนดู Long เช่น “เดี๋ยวเราไปลุยกันเลย” หรือชี้ไปคลิปใต้คอมเมนต์เมื่อมีในต้นฉบับ ไม่ลากคำลาและไม่สร้างคำพูดที่ไม่ได้บันทึก
- ใช้ **Canva Sans** ตามตัวอย่างที่ยืนยัน ไม่ใช้กล่องทึบหรือแผงข้อความแบบ Long ไม่ขีดเส้นใต้
- ซับขาว เน้นคำสำคัญเหลือง พร้อมขอบ/เงาที่อ่านง่าย วางต่ำพอไม่บังหน้าและไม่หลุดขอบ
- ตรวจคำซ้ำ dead air พยางค์ รอยต่อเสียง และความตรงกันของภาพกับคำพูดเช่นเดียวกับ Long
- ตรวจทุก caption event ในไฟล์ encode รวมทุกบรรทัดที่ขึ้นใหม่ อย่าเช็กเพียงภาพตัวอย่างกระจายไม่กี่จุด
- ASS ต้องรักษา linebreak escapes ก่อนใส่รูปแบบคำ ห้ามให้คำสั่งฟอนต์/สีปรากฏเป็นข้อความในคลิป
- ฟอนต์อ้างอิงในเครื่อง: `EP216/work/graphics/assets/CanvaSans-Bold.ttf` ตรวจ glyph ภาษาไทยใน export จริง
- เมื่อใช้ renderer ที่เกี่ยวข้อง ให้รัน `EP219/short-v4/check_captions.py` พร้อมการตรวจภาพจริง

## 7. YouTube Package — ไฟล์ข้อความเดียว

ชื่อ `<EP>_Package.txt` แบบ UTF-8 หัวเอกสาร `<EP> — ชุดเนื้อหา` ตามลำดับ:

1. Title
2. แคปชันโพสต์ long video
3. แคปชันโพสต์ short video — ใช้ร่วมกันบน YouTube Shorts / Facebook / TikTok
4. แคปชันโพสต์ short video IG
5. YouTube Description รวม Timeline
6. YouTube Tags

Title และแคปชันทุกหมวดมี `ตัวหลัก`, `สำรอง 1`, `สำรอง 2` เนื้อหาต้องตรงกับคลิป ไม่แต่งความสามารถ ผลลัพธ์หรือข้อเสนอที่ไม่มีจริง

### แคปชัน

- Long ใช้รูปแบบข้อเสนอทรัพยากรฟรีได้เมื่อมีจริง เช่น `ฟรี! พิมพ์ "<keyword>" ผมส่งเนื้อหาทั้งหมดให้ครับ ☺️ : <title>`
- Short หลัก/สำรอง ใช้ชื่อคลิปหรือข้อความโพสต์ที่ตรงกันแบบคำต่อคำร่วมกันบน YouTube Shorts, Facebook และ TikTok ไม่แต่ง hook ทั่วไปคนละชุด และระบุแพลตฟอร์มที่ใช้ร่วมกันใน Package
- IG ต้องเริ่มด้วย `ฟรี✨ พิมพ์ "<keyword>"` แล้วบอกว่าจะส่งลิงก์คลิปเต็มหรือแหล่งเรียนรู้ที่เกี่ยวข้อง ใช้ keyword ของ EP นั้น เช่น EP216 ใช้ `jev` ไม่ใช้ keyword ของตอนเก่าเป็นค่าเริ่มต้น
- “ฟรี” หมายถึงทรัพยากรที่ให้ ไม่ได้แปลว่าผลิตภัณฑ์ฟรี และไม่อ้างว่าตั้งระบบตอบคอมเมนต์อัตโนมัติแล้ว
- แก้แคปชันอย่างเดียวต้องคงชื่อ วิดีโอ ปก Description Timeline และ Tags เดิม

## 9. การตรวจคุณภาพและ Preview

ก่อน full encode ให้ตรวจชุด preview สั้นจากแผนเดียวกับไฟล์จริง: เปิดคลิป รอยตัดที่แก้ timecode ของผู้ใช้ ภาพเปรียบเทียบ ตำแหน่งหน้า/ปุ่ม ข้อความ CTA เสียง ปิดคลิป และตัวอย่างความคมชัดเทียบต้นฉบับ แก้จุดที่ไม่ผ่านก่อนเรนเดอร์เต็ม

ก่อนส่งแต่ละวิดีโอ:

- เทียบต้นฉบับกับ export ที่เวลาเดียวกัน โดยเฉพาะตัวหนังสือบนหน้าจอ ใบหน้าและช่วงเคลื่อนไหว ใช้ต้นฉบับจริง ไม่ใช้ Drive streaming preview เป็นแหล่งตัดต่อ
- ตรวจ resolution, frame rate, codec และการตั้งค่าบีบอัดให้เหมาะกับต้นฉบับ อย่าลดคุณภาพจนตัวอักษรแตกเพื่อเร่งส่ง และอย่าใช้การ upscale เป็นหลักฐานว่ารายละเอียดกลับมาแล้ว
- Decode ไฟล์ ตรวจจำนวนเฟรม duration ความตรงกันของภาพ/เสียง loudness และ true peak ตามแผน
- ตรวจประโยคและภาพรอบรอยต่อ เซนเซอร์ ขอบกราฟิก และ Short ทุก caption event
- แยกให้ชัดว่าได้ฟังจริงหรือเพียงใช้ ASR/waveform ห้ามรายงานอย่างหนึ่งแทนอีกอย่าง
- Decode ผ่านและ hash ตรงพิสูจน์ความสมบูรณ์ของไฟล์/การส่ง แต่ไม่ได้พิสูจน์ความคมชัดหรือคุณภาพการตัดต่อ
- EP219 Long ถูกผู้ใช้ปฏิเสธด้านสไตล์ ห้ามใช้เป็นตัวอย่างที่ยอมรับ การโพสต์ YouTube หรือผ่าน technical QA ไม่เท่ากับอนุมัติด้านเนื้อหา/สไตล์
- ตรวจตามขอบเขตให้ครบแล้วส่งทันที ใช้หลักฐานเดิมในส่วนที่ไม่เปลี่ยน

## 11. Runtime ที่ติดตั้งบนเครื่องนี้

อ่าน `~/.local/share/bbn-ai-cut/README.md` ก่อนเรียกโมเดล และใช้ environment เดิม:

- Qwen / MLX Whisper / Silero: `~/.local/share/bbn-ai-cut/venvs/mlx/bin/python`
- Typhoon CTC / Thai Whisper: `~/.local/share/bbn-ai-cut/venvs/thai/bin/python`
- โมเดลและ hashes: `~/.local/share/bbn-ai-cut/models.json`
- หลักฐาน smoke checks: `~/.local/share/bbn-ai-cut/checks/`

เครื่อง 16 GB ต้องรันโมเดลหนักทีละตัว ใช้โหมด offline ตามสกิล ไม่ดาวน์โหลดโมเดลซ้ำ ไม่เปลี่ยนไปส่ง footage เข้า cloud โดยพลการ ใช้ FFmpeg และเครื่องมือที่มีอยู่สำหรับการตัด/ซิงก์/encode; ใช้ HyperFrames และสกิลที่เกี่ยวข้องเมื่อทำ motion graphics ตามงานจริง

พาธในเอกสารนี้อ้างถึงเครื่องและโปรเจกต์ปัจจุบัน เมื่อนำไปเครื่องใหม่ต้องตรวจว่ามี runtime, assets, ฟอนต์ และสิทธิ์ Drive/Telegram พร้อมก่อน เอกสารไม่ได้รับรองว่าระบบเหล่านั้นถูกติดตั้งบนเครื่องใหม่แล้ว
