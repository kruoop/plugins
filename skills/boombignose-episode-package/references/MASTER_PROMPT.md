# STEP 0 — อ่านคลิปให้เข้าใจก่อน

โฟลเดอร์ EP จะมีคลิปยาว กับคลิปสั้น (ไฟล์ที่มี `TK` ในชื่อ = แนวตั้งสำหรับ Shorts/TikTok)
ถ้ามีหลายเวอร์ชัน ใช้ตัวล่าสุดที่ไม่มีลายน้ำ และเช็กว่าความยาวตรงกับตัวเก่าไหม
ถ้าไม่ตรง ต้องทำ Timeline ใหม่

**หาไฟล์คำบรรยายก่อนเสมอ** — `captions.sbv` หรือ `.srt` ในโฟลเดอร์ EP
- **ถ้ามี** → ใช้เป็นแหล่งความจริงหลัก Timestamp ตรงวินาที
- **ถ้าไม่มี** → อ่านคลิปด้วยการดึงเฟรม (วิธีด้านล่าง) แล้วระบุในไฟล์ว่า timestamp แม่น ±10 วินาที
  พร้อมบอกว่าถ้าวาง `captions.sbv` มาจะปรับให้ตรงวินาทีทันที

**เครื่องนี้ไม่มี ffmpeg / whisper / homebrew** วิธีที่ใช้ได้คือคอมไพล์ Swift CLI
- ดึงเฟรม: `AVAssetImageGenerator` (คลิปแนวตั้งต้องตั้ง `maximumSize` เท่าด้านยาว ไม่งั้นโดนย่อ)
- ความยาวคลิป: `afinfo` ที่ติดมากับ macOS
- ตัดพื้นหลังคน: `VNGenerateForegroundInstanceMaskRequest`
- ย่อรูป: `sips -Z`

**เครื่องมือถาวร ไม่ต้องคอมไพล์ใหม่ทุกครั้ง** อยู่ที่ `~/.local/bin/`
- `bbn-shot <html> <out.png> <W> <H>` — เรนเดอร์ HTML เป็น PNG (ห้ามใช้ทำปก ตามกฎ 2026-10-22 ข้อ 3)
- `bbn-mark <claude|dewhite|inkwhite> <in> <out>` — สกัดโลโก้ให้พื้นโปร่งใส

**เรื่องถอดเสียงไทย** `SFSpeechRecognizer` รองรับ `th-TH` จริง (เคยเข้าใจผิดว่าไม่รองรับ)
แต่เครื่องนี้ไม่มีชุดข้อมูลออฟไลน์ (`supportsOnDeviceRecognition = false`)
ถ้าใช้ **เสียงทั้งคลิปจะถูกส่งขึ้นเซิร์ฟเวอร์ Apple** ซึ่งเป็นการส่งคลิปที่ยังไม่เผยแพร่ออกไปข้างนอก
**ห้ามทำเองโดยไม่ถามเจ้าของช่องก่อน** ทางที่ควรใช้คือโหลด auto-caption จาก YouTube หลังอัป

ดึงเฟรมทุก 30 วินาทีก่อนเพื่อจับโครง แล้วดึงถี่ขึ้นเฉพาะช่วงรอยต่อบท

## เป้าหมายสำคัญ — ต้องพร้อมคัดลอกลง Skool จริง

ไฟล์นี้ไม่ใช่รายงานการทำงาน แต่เป็นต้นฉบับสำหรับวางใน Skool โดยตรง เนื้อหาต้องอ่านเรียบร้อยบนมือถือและไม่ทำให้เจ้าของช่องต้องมานั่งลบข้อความภายในออกเอง

**ห้ามปนข้อความหลังบ้านลงในเนื้อหา 4 แท็บ** เช่น
- สถานะ `content_review`, เวอร์ชันไฟล์ หรือประโยคว่า “รออนุมัติ”
- Blocker, Character count, ที่มาของข้อมูล, รายงานสิ่งที่เสริมนอกคลิป

### 🍀 [ชื่อที่ตั้งตามเนื้อหาคลิป]
หน้าอธิบายหลักของทั้งคอร์ส คำอธิบาย บริบท และวิธีใช้ทั้งหมดอยู่ที่นี่

- **📝 สรุปเนื้อหาสำคัญ** — เปิดด้วย **"ทำไมต้องทำแบบนี้"** ก่อนเสมอ ไม่ใช่กระโดดเข้าวิธีทำ
  ให้เหตุผลเชิงคุณค่าเป็นข้อ ๆ แล้ว **ยอมรับข้อเสียตรง ๆ** ด้วย จะน่าเชื่อถือกว่ามาก
  ต้องมี **การเปรียบเทียบให้คนไม่ใช่สายเทคเห็นภาพ** อย่างน้อยหนึ่งจุด
  แล้วอธิบาย workflow เป็นขั้นตอน มี diagram แบบลำดับตรง ๆ "ขั้นที่ 1, 2, 3..." พร้อมลูกศรไหลลง
  **ห้ามใช้ธีมเกม/รถแข่ง** (ด่าน, START/FINISH, บอสใหญ่)
- **🛠️ อุปกรณ์ที่ใช้** — ใช้ลิสต์ธรรมดารูปแบบ `- **ชื่อเครื่องมือ** — บทบาท` ปิดท้ายว่าลิงก์ทั้งหมดอยู่ที่แท็บ 💎 ห้ามใส่รายการเครื่องมือในกล่องโค้ด
- **📁 การตั้งค่าและการใช้งาน** — สเต็ปเรียงลำดับ ละเอียดพอทำตามได้โดยไม่ต้องเดา
  ข้อมูลอ้างอิงต้องเป็นแบบที่คนอ่านเอาไปเทียบกับเครื่อง/งานตัวเองได้ ใช้ลิสต์ตัวหนาคั่นขีดยาวหรือตาราง Markdown เมื่อช่วยให้เปรียบเทียบง่าย ห้ามใช้กล่องโค้ดจัดคอลัมน์
  ถ้ามีสูตรคิดเร็วให้ใส่ด้วย
- **💡 ข้อควรระวัง / Tips** — จุดที่คนพลาดบ่อย ความปลอดภัย และข้อจำกัดของระบบ

### 🔥 ต่อยอด Exclusive
- เขียนอิสระตามเนื้อหาจริง ไม่ยึดโครงตายตัว ไม่แบ่งระดับ
- เปิดด้วย **ตัวเลขหรือการเปรียบเทียบที่จับต้องได้** หัวข้อมี emoji และบอกผลลัพธ์
- ถ้าเนื้อหาเอื้อ ให้มีมุมธุรกิจ (รับงาน / ขายเป็นบริการต่อ)
- ถ้าคลิปไม่มีมุมต่อยอดมาก เขียนสั้น ๆ เป็นแนวทางพอ
- **เป้าหมายสำคัญสุด: ต้อง exclusive กว่า YouTube** เจาะลึกสิ่งที่คลิปไม่ได้พูด
  หรือขยายจากสิ่งที่คลิปแตะไว้แค่ผิว ๆ
- ปิดท้ายหน้านี้เสมอด้วย
  `❓ ติดปัญหาตรงไหน โพสต์ถามได้เลยที่แท็บ Community พร้อมแนบข้อความ error ที่เจอ ผมและเพื่อนสมาชิกจะช่วยกันดูให้ครับ`

### 💎 Source Code เทมเพลต
หน้านี้คือ **"จุดแปะของ" ไม่ใช่หน้าอธิบาย ต้องสั้น**
1. **🔗 ลิงก์สำคัญ** — ใช้ `- <ชื่อ> — @url:` ตามด้วย URL ใน backtickทุกบรรทัด ชื่อไม่ต้องมีวงเล็บ; ถ้ามาจาก Doc ให้ใช้เฉพาะ URL ที่อยู่ใน Doc จริง ห้ามใส่ลิงก์ Doc/โฟลเดอร์ และห้ามใส่ลิงก์พันธมิตรซ้ำเมื่อมีอยู่ด้านบนแล้ว
2. **Prompt / เทมเพลตที่แจก** — วางเต็ม ๆ ในกล่องโค้ดให้ก๊อปไปใช้ได้เลย

ใส่ตารางอ้างอิงกับชุดคำสั่งที่ใช้บ่อยเพิ่มได้ ตราบใดที่ไม่อธิบายซ้ำกับ 🍀

**ห้าม** เขียนคำอธิบายยาว ๆ ในหน้านี้ · **ห้าม** สรุปซ้ำกับแท็บ 🍀 ให้อ้างอิงถึงกันแทน
เช่น "วิธีใช้ทีละขั้นอ่านที่แท็บ 🍀"

## กติกาไฟล์แจก
- เข้าไปดูไฟล์จริงในโฟลเดอร์ Drive ที่ระบุใน INPUT แล้วใส่ชื่อไฟล์ + ลิงก์จริงทุกตัว
- ข้ามไฟล์ขยะ: ขึ้นต้นด้วย `._` หรือ `~$` และไฟล์คลิป `.mov`
- **ถ้าไฟล์หายหรือโฟลเดอร์ว่าง แจ้งทันที** แล้วบอกตรง ๆ ว่าเป็น EP รีวิว/ปูพื้นฐาน
  จากนั้นแจกเป็น Prompt/เทมเพลตที่เขียนขึ้นจากขั้นตอนในคลิปแทน
- ถ้ามีไฟล์ workflow n8n (.json) ให้แกะโครงสร้างจริงมาใช้เขียนสรุป และวาดผัง workflow เป็นรูปให้ด้วย (ดูบนมือถือได้)
- เช็กลิสต์ใส่เฉพาะเมื่อเป็นการติดตั้งหลายระบบที่พลาดง่าย ไม่ต้องมีทุกครั้ง

## กฎการแบ่งเนื้อหา (ห้ามเด็ดขาด)
- 🍀 = คำอธิบายทั้งหมด บริบท workflow ขั้นตอนติดตั้ง วิธีใช้ ข้อควรระวัง
- 🔥 = การต่อยอด สิ่งที่คลิปไม่ได้พูด มุมธุรกิจ
- 💎 = ลิงก์ + Prompt/เทมเพลต เท่านั้น

อ้างถึงกันได้ **ห้ามก๊อปซ้ำ**

## กฎการจัดรูปแบบ
- **ใช้ตาราง Markdown ใน Skool ได้** เมื่อข้อมูลเหมาะกับการเปรียบเทียบเป็นแถว/คอลัมน์ ทำตารางให้กระชับและอ่านบนมือถือได้
- **ห้ามใส่ตารางอ้างอิงหรือผังขั้นตอนไว้ในกล่องโค้ดเด็ดขาด**
  Skool แตกกล่องโค้ดหลายบรรทัดออกเป็นชิปสีเทาทีละบรรทัด ยิ่งบรรทัดเยอะยิ่งพัง
  และการจัดคอลัมน์ด้วยช่องว่างก็ไม่รอด เพราะตัวอักษรไทยกว้างไม่เท่ากันแม้ในฟอนต์ monospace
  ให้ใช้ **ลิสต์ธรรมดา** แทน หัวข้อตัวหนา คั่นด้วยขีดยาว
  `- **Pinterest** — คลังภาพดีไซน์ ใช้หา Ref ก่อนสั่งงาน`
  ผังขั้นตอนใช้ **ลิสต์เลข** `1. 2. 3.` ไม่ใช่ ASCII art ที่มีลูกศร `|` กับ `v`
- กล่องโค้ดเก็บไว้ใช้เฉพาะของที่ต้องคัดลอกไปวางทั้งก้อนจริง ๆ เท่านั้น
  คือ Course description, Prompt เต็ม และคำสั่งที่พิมพ์ตรง ๆ นอกนั้นเป็นข้อความปกติหมด
- **ห้ามเขียนคำว่า "Page 1/2/3"** และ **ห้ามใส่ timestamp ทุกกรณี**
- นับตัวอักษร description ด้วยโค้ดทุกครั้งก่อนส่ง แต่รายงานตัวเลขไว้ใน `หมายเหตุสำหรับเจ้าของช่อง` เท่านั้น ห้ามวางต่อท้าย Course description ที่จะนำเข้า Skool

## QA ก่อนส่งไฟล์ Skool — ต้องผ่านทุกข้อ

- [ ] ชื่อแท็บครบ 4 แท็บและเรียงถูก
- [ ] อ่านเฉพาะเนื้อหาแต่ละแท็บแล้วต่อเนื่อง ไม่เห็นสถานะงานหรือคำสั่งภายใน
- [ ] ไม่มี `---`, Character count, Blocker, แหล่งที่มา หรือรายงาน Agent ปนใน 4 แท็บ
- [ ] 🌟 สั้นและมีลำดับเรียนชัด
- [ ] 🍀 เปิดด้วย “ทำไม” มี Workflow วิธีใช้ การทดสอบ ข้อเสียและความปลอดภัย
- [ ] 🔥 ไม่สรุปซ้ำ 🍀 และมีของเพิ่มที่นำไปใช้ได้จริง
- [ ] 💎 มีเฉพาะไฟล์ ลิงก์ Prompt/Code และเช็กก่อนรัน
- [ ] ตาราง Markdown (ถ้ามี) กระชับและอ่านบนมือถือได้; ไม่ใช้กล่องโค้ดกับตาราง ผัง หรือเนื้อหาที่ไม่ต้องก๊อปทั้งก้อน
- [ ] ไม่มี placeholder ในเวอร์ชันที่จะนำเข้า Skool จริง
- [ ] Course description ผ่าน 480 ตัวอักษรด้วยการนับจากข้อความจริงเท่านั้น

# กฎรวมที่ใช้กับทุกชิ้นงาน

## สไตล์การเขียน
- ภาษาไทยปนอังกฤษธรรมชาติ ศัพท์เทคนิคใช้อังกฤษ เป็นกันเองแต่มืออาชีพ
- อธิบายให้คนไม่ใช่สายเทคเข้าใจ ใช้การเปรียบเทียบเมื่อเรื่องซับซ้อน
- **สอนจบในตัว ห้ามอ้างอิงว่าต่อยอดจาก EP เก่า** ถึงแนวคิดจะเคยสอนมาแล้ว
  ก็อธิบายใหม่ให้ครบในบริบทของคลิปนี้
- ข้อความตอบสมาชิกที่เป็นภาษาไทย ใช้ ค่ะ/นะคะ

## ความถูกต้อง
- **ข้อมูลที่ไม่รู้จริง ห้ามเดา** ให้ถามแทน
- ถ้าคำบรรยายกับภาพหน้าจอขัดกัน **ยึดภาพ** แล้วไปดึงเฟรมมายืนยันก่อนเขียน
- **ถ้าเสริมเนื้อหานอกเหนือจากคลิป ต้องบอกท้ายงานว่าเสริมตรงไหนบ้าง**

## ความปลอดภัยและความเป็นส่วนตัว
ตรวจทุก EP แล้วรายงานในหมายเหตุก่อนอัปโหลด
- ชื่อ/รูป/โปรไฟล์คนจริงบนจอ → บอกช่วงเวลาที่ควรเบลอ **และห้ามให้โผล่บนปกหรือใน Title เด็ดขาด**
- อีเมล เบอร์ เลขบัญชี บนจอ → บอกให้เบลอ
- เรื่องการแพทย์ การเงิน กฎหมาย → ใส่ disclaimer ใน Description
  และ **ห้ามใส่คำที่เป็นการเคลมลงในชื่อคลิปหรือภาพปก**
- รหัสผ่าน / OTP / เลขบัตร → ในคู่มือต้องเขียนย้ำว่าคนกรอกเอง ห้าม AI กรอกแทน

# DELIVERY GATE — ส่งให้ตรวจทันที แล้วหยุดรอคำสั่ง Draft

เมื่อสร้างหรือแก้ Title/Description, Guide, Skool หรือปก Candidate ของ EP ใดเสร็จ:

1. ส่งข้อความ Review ของ EP นั้นพร้อมแนบไฟล์เนื้อหาจริงและปก Candidate เข้าแชท AutoYT_Bot/Telegram ทันที ห้ามเก็บไว้เฉพาะในเครื่องหรือ Drive
2. ทำและส่งทีละ EP เท่านั้น ถ้ามีหลาย EP ให้ส่ง EP แรกให้ตรวจและหยุดรอ feedback ก่อน ห้ามทำหรือส่งหลาย EP รวดเดียว
3. หลังส่ง Review ต้องหยุดที่สถานะ `awaiting_content_review` ห้ามสร้างหรือแก้ YouTube Draft, Skool Draft, อัปโหลดวิดีโอ หรือเผยแพร่ จนกว่าเจ้าของช่องจะสั่งเฉพาะ EP/เวอร์ชันว่าให้ “สร้างดราฟ”
4. เมื่อได้รับคำสั่งสร้าง YouTube Draft ให้ใส่เฉพาะเนื้อหาและไฟล์ที่อนุมัติใน YouTube Studio แล้วปิด/ออกจากขั้นตอนอัปโหลดเพื่อให้ระบบเก็บเป็น `Draft` เอง **ห้ามเลือก Private, Unlisted, Public หรือ Schedule และห้ามใช้ YouTube Data API อัปโหลดแทน** เพราะการสร้างวิดีโอด้วย API ต้องกำหนด visibility และอาจเริ่มนับเวลาบนแพลตฟอร์ม ตรวจกลับให้เห็นสถานะ `Draft` เท่านั้นก่อนรายงานสำเร็จ
5. การตรวจพบไฟล์ใหม่ไม่ใช่คำอนุมัติสร้าง Draft และการที่เคยอนุมัติ EP ก่อนหน้าไม่ครอบคลุม EP ถัดไป
6. หาก Delivery ล้มเหลว ห้ามถือว่าส่งแล้ว ต้อง retry ผ่าน `bot-chat:auto-post-youtube` และรายงาน failure ที่ตรวจได้
