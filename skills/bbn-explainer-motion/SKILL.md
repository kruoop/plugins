# BBN Explainer Motion

## การใช้ใน workflow ของ auto-post-content

ใช้เสริมทั้ง Long V2 และ Short เฉพาะ explanation ตามเนื้อหาจริง ไม่บังคับทุก pattern หรือแปลง hands-on demo เป็นกราฟิก Long รักษา V2; Short หลังฮุคใช้โมชั่นครึ่งบนกับวิดีโอกล้องจริงพร้อมห้องเดิมครึ่งล่าง ไม่ไดคัตคน ตาม bbn-ai-short-fullscreen รวมประโยคเกริ่นว่าจะสอนอะไรและการอธิบายเครื่องมือ กลับหน้าจอ/ผลงานจริงตรงเสียงชวนดูหรือเริ่มพาทำ ไม่ใช้ B-roll ค้างแทนแนวคิด และไม่ตัดสินจากชื่อ segment เก่า พาธ panda/ชื่อ HyperFrames ในเอกสารนำเข้าไม่พิสูจน์ว่าติดตั้ง ให้ตรวจ runtime ปัจจุบัน ไม่ติดตั้ง engine ใหม่เพียงเพราะพาธเดิมไม่มี

สร้างกราฟิกที่ทำให้ผู้ชมเห็นว่า **กำลังพูดถึงอะไร อะไรเคลื่อนจากไหน ผ่านขั้นตอนใด และเกิดอะไรขึ้น** ตามเสียงพูด รวมป็อปอัพเครื่องมือ/สิ่งของ/ส่วนประกอบที่สัมพันธ์กับเนื้อหา ใช้ภาพที่แก้ไขได้และเคลื่อนไหวจริง เป็นสกิลเสริมของงานตัดต่อ ไม่เริ่มตัดเสียงหรือสร้าง Long/Short เพิ่มเอง

ใช้ได้กับทุกหัวข้อและจำนวนเครื่องมือที่เนื้อหาต้องการ Claude/Codex และบอร์ดงานเป็นเพียงตัวอย่างรูปแบบ เลือกวัตถุ โลโก้ และโครงฉากใหม่จากตอนที่กำลังตัด ไม่ใส่สองเครื่องมือนี้หรือ browser window เป็นค่าเริ่มต้นทุกเรื่อง

อ่าน [รูปแบบภาพและโมชั่น](references/motion-patterns.md) เมื่อออกแบบฉาก และ [การผูกเวลาและส่งงาน](references/edit-integration.md) ก่อนลงไทม์ไลน์หรือเรนเดอร์

## สไตล์ Long ปัจจุบัน (ผู้ใช้ 2026-10-21)

**ห้ามใช้อีโมจิในคลิป (ผู้ใช้ 2026-10-21 สั่งทับข้อ 1 และตัวอย่างด้านล่าง):** ไม่ใช้อีโมจิทุกแบบ รวม Fluent Emoji 3D และฟอนต์อีโมจิของระบบ ใช้โลโก้จริงใน tile มุมมน ภาพสินค้า/ฟุตเทจจริง หรือไอคอนวาดเองแบบ SVG สีเต็มมีมิติ (gradient นุ่ม มุมมน ขนาดใหญ่) แทน เกณฑ์ขนาด ตัวหนังสือ และโมชันยังใช้ตามข้อ 1–5

ผู้ใช้ดู EP242 แล้วบอกว่าไอคอนเล็กและไม่น่ารัก ตัวหนังสือเล็ก และโมชันน้อยไป จึงใช้ค่าต่อไปนี้กับ **Long** เป็นค่าเริ่มต้น (Short แผงครึ่งบนใช้ค่าเดิมในแผงของตัวเอง เว้นแต่ผู้ใช้สั่ง):

1. **ไอคอนน่ารักและใหญ่** — ใช้ไอคอนสีสันมีมิติแบบ Fluent Emoji 3D/Color หรือ illustration การ์ตูนมุมมน โลโก้จริงใส่ใน tile มุมมนพื้นขาวเงานุ่มแบบไอคอนแอป ห้ามใช้ไอคอนเส้นบางสีดำ (`ico()` แบบ EP242) เป็นภาพหลัก ขนาดขั้นต่ำวัดบนเฟรม 1920×1080 สุดท้ายหลังย่อแผง: ไอคอนหลักของฉาก ≥ 220px, ไอคอน/โลโก้ในรายการ ≥ 140px
2. **ตัวหนังสือใหญ่** — หัวข้อ ≥ 80px, ป้าย/ชื่อใต้ไอคอน ≥ 44px, ข้อความในการ์ด ≥ 40px, ห้ามต่ำกว่า 36px ทุกกรณี วัดบนเฟรมสุดท้ายเช่นกัน ถ้าใส่ไม่พอให้ลดจำนวนคำหรือแบ่งฉาก ไม่ย่อตัวอักษร
3. **โมชันมากขึ้น** — ช่วงอธิบายต้องไม่มีภาพนิ่งสนิทเกิน ~2.5 วินาที: ประกอบฉากทีละชิ้นตามคำพูด แล้วระหว่าง hold มี idle motion (ไอคอนลอย/หายใจ scale 1→1.03, ไฮไลต์วนรอบ loop, เคอร์เซอร์ชี้/คลิกการ์ด) เปลี่ยนฉากด้วย blur/slide/morph ไม่ตัดแข็ง รายละเอียดใน motion-patterns หัวข้อ F
4. ฉากโมชันเต็มเฟรมใช้เลย์เอาต์ "หน้าจอใหญ่ + ผู้พูดเล็ก" ของ V2 (ผู้พูดกรอบเล็กขวาล่าง) เพื่อให้กราฟิกใหญ่ ไม่บีบโมชันลงแผง 1504×846 จนตัวเล็ก
5. ไม่มีข้อความเหลืองด้านบนจอ จุดเน้นใช้สีส้มแดงของสไตล์นี้

**ผู้ใช้อนุมัติสไตล์นี้เป็นค่าเริ่มต้นของ Long แล้ว (2026-10-21)** ตัวอย่างอ้างอิงคือ [approved-sample-2026-10-21](references/approved-sample-2026-10-21/) (`BBN_motion_style_sample.mp4` + `index.html` HyperFrames 0.8.159 รวม slot fill, branch choose, cursor click, progress, blur handoff, idle motion) ใช้เป็นแม่แบบขนาด/จังหวะ/ภาษาภาพ แต่เปลี่ยนเนื้อหา ไอคอน และเวลาให้ตรงเสียงของ EP จริง asset ที่ไฟล์อ้างถึง (gsap, ฟอนต์ไทย, โลโก้, face.png) นำมาจาก assets ของ EP/สกิล bbn-ai-edit อีโมจิในตัวอย่างใช้ฟอนต์ Apple Color Emoji ของเครื่อง งานจริงให้ใช้ไฟล์ Fluent Emoji 3D ที่ดาวน์โหลดแล้ว 60 ไอคอนใน [bbn-ai-edit/assets/shared/fluent-emoji](../bbn-ai-edit/assets/shared/fluent-emoji/SOURCE.md) (PNG 256×256, MIT) คัดลอกไฟล์ที่ใช้เข้า `assets/` ของ composition แล้ววางด้วย `<img>` ไม่ใช้ฟอนต์อีโมจิของระบบ

## ขอบเขตอธิบายกับสอน

**ใช้โมชั่นและป็อปอัพของสกิลนี้เฉพาะช่วงพูดอธิบายเนื้อหา/แนวคิดเท่านั้น** เมื่อเข้าสู่การสอนหรือสาธิต ให้กลับไปใช้คลิปอัดหน้าจอต้นฉบับในเลย์เอาต์สอนเดิมตลอดช่วงนั้น ไม่แทนหน้าจอด้วยกราฟิก และไม่แทรกป็อปอัพจากสกิลนี้ระหว่างสอน ซับและองค์ประกอบที่มีอยู่ในรูปแบบสอนเดิมคงตามงานหลัก

จุดเริ่มสอนคือเริ่มพาผู้ชมทำตามบนหน้าจอ เช่น เปิดเมนู ตั้งค่า หรือชี้ขั้นตอน ไม่ต้องรอจนคลิกครั้งแรก จบโมชั่นรวม exit/transition ให้ครบก่อนเฟรมเริ่มสอน ช่วงอธิบายขั้นตอนหรือรอโหลดภายในการสาธิตยังใช้หน้าจอจริงต่อ กลับมาใช้โมชั่นเมื่อเปลี่ยนเป็นช่วงอธิบายแนวคิดแยกจากการสอนอย่างชัดเจน

## อธิบายให้คนไม่มีพื้นฐานเทค

เมื่อผู้ใช้ขอให้คนทั่วไปเข้าใจ ให้เริ่มจากโจทย์เดียวที่คุ้นเคย เช่น ดูนัดในปฏิทิน แล้วแสดงก่อนเชื่อม → เงื่อนไขการเชื่อม/อนุญาต → ข้อมูลเดินทางกลับ → ผลที่นำไปใช้ ก่อนเอ่ยศัพท์เทคนิค ไม่เปิดด้วยตัวย่อเรียงกันหรืออุปมาที่ต้องรู้ศัพท์เพิ่ม เช่น USB-C หากคนดูยังไม่รู้พื้นฐานนั้น

ใช้ภาษาชีวิตประจำวันโดยรักษากลไกจริง: protocol เป็นกติกาการสื่อสาร ไม่ใช่ AI อีกตัวหรือผู้ตัดสินสิทธิ์เอง เก็บ host/server/API ไว้ใน notes ของคนผลิตเมื่อไม่จำเป็นต่อบทเสียง และไม่ทำภาพว่าเชื่อมได้ทุกแอปหรือทุกบัญชีทันที การเปรียบเทียบกับคนช่วยงานเป็นอุปมา ไม่ใช่หลักฐานการทดลองจริง

## เลือกฉากจากความหมาย

| คำอธิบาย | รูปแบบที่เลือก |
|---|---|
| งานไหลผ่านขั้นตอน, AI ทำงานต่อ, pipeline | **Workflow board:** การ์ดเคลื่อนผ่านคอลัมน์ |
| รับข้อมูลหลายแหล่ง, เชื่อมเครื่องมือ, รวมข้อมูล | **Converging paths:** การ์ดวิ่งตามเส้นเข้าโหนดกลาง |
| เปลี่ยนประเด็นระหว่างสองฉากอธิบาย | **Vertical slide:** ฉากเดิมขึ้น ฉากใหม่ขึ้นจากล่าง พร้อม blur สั้น ๆ |
| กล่าวชื่อเครื่องมือ สิ่งของ ฟีเจอร์ หรือส่วนประกอบ | **Contextual pop-up:** โลโก้/ไอคอน/การ์ดภาพปรากฏตรงคำพูด |
| อธิบายการสร้างเว็บ หน้าจอ หรือระบบทีละส่วน | **Progressive build:** เพิ่มองค์ประกอบเข้าโครงเดียวตามลำดับที่พูด |

ไม่บังคับใส่ครบทุกแบบทุกคลิป แต่ใน Long ให้ป็อปอัพทุกสิ่งสำคัญที่เอ่ยถึงในช่วงอธิบาย (เครื่องมือ สิ่งของ ขั้นตอน ตัวเลขที่มีหลักฐาน) เว้นเฉพาะคำเชื่อมหรือคำนามทั่วไปที่ไม่มีภาพสื่อ กราฟิกแสดงสิ่งและความสัมพันธ์ ไม่ใช่เพียงหัวข้อเด้งเข้าแล้วค้าง ซับคำพูดยังคงทำหน้าที่อ่านตามเสียง ส่วนป้ายในกราฟิกเป็นชื่อสั้น ๆ

## ขั้นตอนทำงาน

1. อ่านบรีฟและแผนตัดต่อปัจจุบัน ใช้ transcript และ source→final mapping ที่มีอยู่ ฟังเฉพาะช่วงอธิบายเพื่อหาคำที่บอกต้นทาง การกระทำ และปลายทาง หากยังไม่มีคลิป/เสียง ให้ทำ storyboard และระบุว่าเวลายังเป็นค่าประมาณ
2. แบ่งช่วงเป็น `explanation` กับ `teaching` ก่อนเลือกกราฟิก ใช้โมชั่นเฉพาะ explanation ที่ภาพช่วยอธิบายความสัมพันธ์ ใช้ฉากเต็มหรือแผงข้างตามเลย์เอาต์ที่รับรองแล้ว เมื่อเข้า teaching คืนคลิปอัดหน้าจอและเลย์เอาต์สอนเดิมตั้งแต่เฟรมแรกของช่วงและรักษาตลอดการสอน
3. บันทึก cue ต่อฉาก: `final_start_frame`, `final_end_frame` แบบ `[start,end)`, `fps`, คำพูดและคำยึดจังหวะ, รูปแบบ, โหนด/คอลัมน์, การเคลื่อนและผลที่แสดง, พื้นที่ซับ/ผู้พูด, และสถานะเวลาว่าเป็นแผนหรือเช็กกับเสียงแล้ว ป็อปอัพแต่ละชิ้นมีคำยึดจังหวะ asset ตำแหน่ง entrance/hold/exit และเฟรมของเหตุการณ์เมื่อเช็กเสียงแล้ว
4. วางภาพตอนอ่านชัดที่สุดก่อน แล้วเพิ่ม entrance → การกระทำหลัก → settle/hold → transition/exit ยึดคำสำคัญกับเหตุการณ์ที่ตรงความหมาย ให้เห็นป้ายก่อนการ์ดเคลื่อน และมีเวลามองผลหลังเคลื่อนเสร็จ
5. ใช้ runtime ที่มีอยู่ แนะนำ HyperFrames + GSAP + SVG สำหรับงานใหม่ อ่านสกิล `hyperframes:hyperframes` และ `hyperframes:hyperframes-cli` เมื่อใช้จริง; compositor เดิมใช้ได้ถ้า seek ตามเฟรมและส่งงานแก้ไขได้ ตรวจ `~/.local/share/bbn-ai-cut/README.md` และโหลด `env.sh` ในโฟลเดอร์เดียวกันก่อนใช้เครื่องมือ (ถ้ามีบนเครื่องนี้) ไม่ติดตั้ง engine ใหม่เพียงเพื่อทำรูปแบบเหล่านี้
6. เรนเดอร์ช่วงสั้นที่มีการเคลื่อนและรอยต่อ ตรวจกับเสียงจริง แก้ข้อผิดพลาดแล้วประกอบเข้าคลิปตามขอบเขตที่ได้รับคำสั่ง ส่งไฟล์วิดีโอจริงพร้อมซอร์สแก้ไขได้และ cue manifest เมื่อผู้ใช้ขอสร้าง/แทรกโมชั่น ไม่จบเพียง prompt หรือ storyboard

## กติกาด้านภาพและความหมาย

- ค่าเริ่มต้นจากตัวอย่าง: พื้นขาวนวล การ์ดขาวมุมมน คอลัมน์เทาอ่อน ตัวอักษร/เส้นดำ และส้มแดงเน้นคำสำคัญ หากงานมีสไตล์ที่รับรองแล้ว ใช้สไตล์นั้นกับโครงโมชั่นนี้ รายละเอียดอยู่ใน motion-patterns
- ใช้ชื่อแหล่งข้อมูล ขั้นตอน และทิศทางตามคำพูด ไม่เติมสถานะ “สำเร็จ/ตรวจผ่าน/อนุมัติแล้ว”, ตัวเลข หรือฟีเจอร์ที่ไม่มีหลักฐาน คำว่า “ตรวจสอบ” ให้แสดงกำลังตรวจ ไม่แสดงผลผ่าน
- ใช้โลโก้ที่มีและตรงเครื่องมือจริงใน tile มุมมน หากไม่มี ใช้ไอคอน SVG วาดเองแบบสีเต็มมีมิติพร้อมชื่อ (ห้ามอีโมจิ) ไม่ใช้ไอคอนเส้นบางเป็นภาพหลัก ไม่สร้างหน้าตา UI ปลอมให้ดูเหมือนหลักฐานการสาธิต
