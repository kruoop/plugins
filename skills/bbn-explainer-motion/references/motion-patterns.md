# ภาพและโมชั่นตามตัวอย่าง

รูปแบบทั้งหมดในไฟล์นี้ใช้เฉพาะช่วงอธิบายเนื้อหา/แนวคิด เมื่อเป็นการสอนหรือสาธิตให้ใช้คลิปอัดหน้าจอและเลย์เอาต์สอนเดิมตามกติกาใน SKILL.md แม้เนื้อหาการสอนจะกล่าวถึงเครื่องมือหรือส่วนประกอบที่ทำเป็นป็อปอัพได้ก็ตาม

ต้นทางคือ screen recording ที่ผู้ใช้ให้วันที่ 2026-10-09 ยาวประมาณ 3.65 วินาที เห็นฉาก Autonomous ที่มีบอร์ดงาน และ Self-improving ที่มีเส้นจาก Sentry/PostHog/Issues เข้าบอร์ดกลาง สามรูปแบบคือการเคลื่อนบนบอร์ด การเคลื่อนตามเส้น และการเปลี่ยนระหว่างฉาก ไม่ใช่ข้อกำหนดให้สร้างสามฉากทุกครั้ง ชื่อและโลโก้ในตัวอย่างไม่ใช่ข้อความประจำคลิป

## ภาษาภาพ

ค่าแนะนำที่ตีความจากภาพอ้างอิง ไม่ใช่การวัดสี/ฟอนต์ต้นฉบับ:

| องค์ประกอบ | ค่าตั้งต้นที่ 1080p |
|---|---|
| พื้นหลัง | `#EEECE8` ขาวนวล |
| คอลัมน์ | `#DFDCD6` เทาอุ่น |
| การ์ด | `#FFFFFF`, มุมมน 16–24px, เงาเบาระยะสั้น |
| ตัวอักษรและเส้น | `#111111`; ข้อความรอง `#57534E` |
| จุดเน้น | `#D83A17` ส้มแดง เฉพาะคำ/วัตถุสำคัญ |
| ฟอนต์ | `Canva Sans, Noto Sans Thai, sans-serif` |
| ขนาดขั้นต่ำ Long (บนเฟรม 1920×1080 สุดท้าย) | หัวข้อ ≥ 80px (แนะนำ 96–130), ป้าย ≥ 44px, ข้อความการ์ด ≥ 40px, ไม่มีตัวอักษร < 36px; ไอคอนหลัก ≥ 220px, ไอคอน/โลโก้ในรายการ ≥ 140px |
| ไอคอน | สีสันมีมิติ น่ารัก มุมมน (Fluent Emoji 3D/Color, MIT) หรือโลโก้จริงใน tile ขาวมุมมน 28–36px เงานุ่ม; ไม่ใช้ไอคอนเส้นบางสีดำเป็นภาพหลัก |

บันทึก palette, typography และขนาดใน DESIGN.md ของ composition ถ้ามีสไตล์ที่รับรองแล้ว ใช้ของเดิมกับโครงโมชั่นนี้ ตรวจ contrast โดยเฉพาะข้อความส้ม ขนาดขั้นต่ำของ Long เป็นค่าบังคับ (ผู้ใช้ 2026-10-21) วัดหลังย่อแผงในเฟรมที่ encode แล้ว ถ้าพื้นที่ไม่พอให้ลดคำหรือแบ่งฉาก Short ปรับตามแผงของตัวเอง

**ไอคอนน่ารัก:** Fluent Emoji ของ Microsoft (github.com/microsoft/fluentui-emoji, MIT, ตรวจ LICENSE แล้ว 2026-10-21) ชุดเริ่มต้น 60 ไอคอนอยู่ที่ `bbn-ai-edit/assets/shared/fluent-emoji/` พร้อม LICENSE และ `SOURCE.md` (ดาวน์โหลด 2026-10-21) คัดลอกไฟล์ที่ใช้เข้า `assets/` ของ composition ถ้า EP ต้องการไอคอนที่ไม่มีในชุด ขอผู้ใช้ก่อนดาวน์โหลดเพิ่ม แล้วบันทึกใน SOURCE.md เรียนลักษณะ mascot pixel-art/avatar การ์ตูนจากคลิปอ้างอิงได้ แต่ห้ามคัดลอก mascot หรือ avatar ของคนอื่น

ใช้พื้นนิ่ง หัวข้อเด่นด้านบน แผนภาพกลางภาพ เว้นขอบประมาณ 6–8% และพื้นที่ซับตามขอบเขตซับจริง เริ่มด้วย 3–5 โหนด/คอลัมน์และการ์ดไม่กี่ใบเพื่อให้ตามวัตถุหลักได้ การเอียงบอร์ดเล็กน้อยแบบ perspective ใกล้ต้นฉบับเป็นทางเลือก ป้ายไทยยาวเหมาะกับบอร์ดตรงมากกว่า ไม่มี glow/กล้องหมุนเป็นค่าเริ่มต้น

## A. Workflow board — งานผ่านขั้นตอน

ใช้เมื่ออธิบายลำดับงานหรือสถานะของงานเดียวกัน

1. สร้างคอลัมน์ตรงเนื้อหา เช่น “รับเรื่อง → ตรวจสอบ → รออนุมัติ” วางการ์ดหลักที่ต้นทางและเผยชื่อขั้นตอนให้อ่านก่อนเคลื่อน
2. ยกการ์ดด้วย scale/เงาเล็กน้อย เคลื่อนถึงคอลัมน์ถัดไปแล้ววางในช่องที่กำหนด ให้เห็นว่าเป็นการ์ดใบเดิม ไม่ teleport
3. ผูกช่วงเคลื่อนกับคำกริยา เช่น “ส่งต่อ” และการถึงกับคำบอกปลายทาง เก็บการ์ดที่ถึงแล้วให้เห็นสถานะสุดท้าย บอร์ดและป้ายคงตำแหน่ง การ์ดที่สะสมไม่ทับกัน
4. คำว่า “กำลังตรวจ” หยุดที่ขั้นตรวจ คำว่า “ส่งให้ทีมอนุมัติ” จบที่ “รออนุมัติ” แสดงผลผ่าน/อนุมัติแล้วเมื่อเนื้อหาหรือภาพจริงยืนยันเท่านั้น

จังหวะเริ่มต้น: entrance 0.3–0.5s, เดินทาง 0.45–0.8s ต่อขั้น, settle 0.12–0.2s, hold 0.6–1.2s ใช้ ease มีแรงเริ่มและนุ่มตอนจบ เช่น `power2.inOut`/`power3.out` ปรับตามเสียงจริง หากประโยคสั้นให้ลดขั้นหรือรายละเอียด ไม่เร่งทุกอย่างจนอ่านไม่ทัน

กรณีหลายขั้นที่มีความหมาย ให้มีจังหวะหยุดในแต่ละขั้น ถ้าพูดเพียงเส้นทางรวม ใช้การเดินทางครั้งเดียวผ่านขั้นย่อได้ ไม่ทำการ์ดวิ่งสุ่มที่ไม่เกี่ยวกับเสียง

## B. Converging paths — หลายต้นทางมารวมกัน

ใช้เมื่ออธิบายแหล่งข้อมูล การเชื่อมเครื่องมือ หรือการรวมข้อมูล

1. วางต้นทางซ้ายเรียงแนวตั้งและโหนดรับขวา วาดเส้น SVG ก่อนการ์ดวิ่ง ปลายเส้นต่อขอบโหนดรับชัด ใช้ Bézier สำหรับต้นทางบน/ล่างและเส้นตรงสำหรับกลาง ปรับแนวทางได้ตามพื้นที่
2. ปล่อยการ์ดตามลำดับชื่อที่พูด ถ้ากล่าวรวมหลายแหล่งใช้ stagger ประมาณ 0.15–0.3s การ์ดคงขนาดและอ่านออก ไม่จำเป็นต้องหมุนตามเส้น
3. ให้ถึงช่วงคำสำคัญ เช่น “รวมไว้ที่เดียว” โหนดรับตอบสนองเบา ๆ ด้วย scale 1→1.03→1 หรือเน้นขอบ แล้วค้างภาพผลรวม ตั้งต้นเวลาเดินทาง 0.65–1.2s ต่อเส้น ปรับตามประโยค

ทำให้ seek และ render เหมือนกัน: progress `p` ระหว่าง 0–1 มาจากเวลาปัจจุบัน หาจุดด้วย `getPointAtLength(p * path.getTotalLength())` หรือคำนวณ cubic Bézier โดยตรง ตำแหน่ง/opacity/สถานะโหนดรับมาจากเวลาเดียวกัน ไม่อาศัย animation frame ที่สะสมสถานะ เมื่อ seek ย้อนกลับต้องคืนสถานะได้

ถ้า SVG path และ HTML card ใช้พิกัดต่างกัน แปลงจาก viewBox ไป container เดียวกัน ตรวจจุด 0%, 50%, 100% หลัง resize และในแนวตั้ง ไม่สมมติว่า MotionPathPlugin ติดตั้งอยู่ ใช้ plugin เมื่อมีจริงหรือใช้การคำนวณ path เดิม

ทิศทางตามคำพูด ไม่ทำ flow ย้อนกลับเพื่อความสวย loop ใช้เฉพาะการอธิบายรับข้อมูลต่อเนื่องและจำกัดรอบตามความยาวฉาก การกล่าวรายชื่อแหล่งข้อมูลครั้งเดียวไม่ต้องวนหลายรอบ

## C. Vertical slide — เชื่อมสองช่วงอธิบาย

ใช้เมื่อเปลี่ยนแนวคิดหรือแผนภาพ ไม่เติมทุกประโยค ก่อน transition ภาพเดิมยังครบและอ่านออก

ใช้ container สองฉาก: ฉากเดิม y=0→-H ฉากใหม่ y=+H→0 ในช่วงเดียวกัน แนะนำ 0.35–0.55s ปรับให้เข้าจังหวะพูด ทิศขึ้นเหมือนตัวอย่างเป็นค่าเริ่มต้น เพิ่ม directional blur/trail เพียงช่วงความเร็วสูง แล้วคืนภาพคมเมื่อ settle

ใช้ ghost จำนวนน้อยหรือ filter ที่ seek ได้ ตรวจวรรณยุกต์และเส้นดำไม่ทิ้งรอยหลังจบ ไม่มี flash พื้นว่างหรือ exit ซ้ำก่อน transition ใน HyperFrames ใช้ transition mechanism ของเวอร์ชันติดตั้งโดยรักษาภาพเดิมไว้ให้ transition ใช้

การกลับหน้าจอจริงไม่จำเป็นต้องใช้ transition นี้ เลือกรอยต่อที่ทำให้เห็นปุ่มและผลทันตามเสียง

## D. Contextual pop-up — สิ่งที่กำลังพูดถึง

คลิปอ้างอิงเพิ่มเติมยาวประมาณ 1.85s ที่ผู้ใช้ให้ในวันที่ 2026-10-09 มีหน้าต่าง browser กลางภาพ โลโก้/ชื่อ Claude และ Codex ปรากฏข้างหน้าต่าง และส่วนต่าง ๆ ของเว็บประกอบเข้าทีละชิ้น ใช้ลักษณะนี้เป็นหลัก ไม่คัดลอกชื่อ โลโก้ browser address หรือ mascot ที่ไม่เกี่ยวกับตอนใหม่

เลือกป็อปอัพจาก **สิ่งสำคัญในคำพูด**: เครื่องมือใช้โลโก้/ป้ายชื่อ, ข้อมูลใช้การ์ด/ไฟล์, ขั้นตอนใช้ภาพการกระทำ, ส่วนของหน้าเว็บใช้ component นั้น ให้ภาพบอกว่าพูดถึงอะไร ไม่ทำทุกอย่างเป็นกล่องคำเน้นอย่างเดียว ป็อปอัพอาจอยู่ข้างแผนภาพหรือข้างผู้พูดในช่วงที่ไม่บังสิ่งสำคัญ

หัวข้อและจำนวนเครื่องมือไม่จำกัดที่ตัวอย่าง:

| สิ่งที่พูดถึง | ภาพที่เหมาะ |
|---|---|
| โปรแกรม/บริการ/แบรนด์ใด ๆ | โลโก้จริงของสิ่งนั้นพร้อมชื่อ; ไม่มี asset ใช้ป้ายชื่อ |
| ไฟล์ เอกสาร รูปภาพ ข้อมูล | ภาพ/ไอคอนไฟล์ตรงประเภท พร้อมสถานะตามคำพูด |
| คอมพิวเตอร์ โทรศัพท์ กล้อง อุปกรณ์ | ภาพหรือไอคอนอุปกรณ์ที่ถูกประเภท ไม่ใช้โลโก้ AI แทน |
| ค่าใช้จ่าย เวลา ปริมาณ | วัตถุ/ตัวเลขที่มีหลักฐานตามคำพูด; ไม่สร้างสถิติใหม่ |
| คน ทีม บทบาท การส่งต่อ | avatar/ไอคอนบทบาทและเส้นทางตามเนื้อหา |
| เปรียบเทียบหลายตัวเลือก | การ์ดของตัวเลือกจริง จำนวนตามเรื่อง ค่อยเผยตามคำพูด |
| แนวคิดที่ไม่มีภาพตรงตัว | ภาพเชิงอธิบายที่สื่อความหมาย เช่น เมฆเก็บไฟล์หรือจุดเชื่อมข้อมูล |

เลือกภาพหลักให้เหมาะเรื่อง: อาจเป็นเอกสาร อุปกรณ์ กระบวนการ หรือแผนภาพ ไม่บังคับทุกหัวข้ออยู่ในหน้าต่าง browser คำว่า “หลายเครื่องมือ” ไม่ได้หมายถึงจำกัดสอง badge; หากมีหลายรายการให้แบ่งจังหวะ/กลุ่มและค้างภาพรวมที่อ่านได้

1. ทำรายการคำยึดจังหวะ→วัตถุจาก transcript ของตอนนั้น เช่น “เครื่องมือ A”→badge ของ A, “ไฟล์ PDF”→เอกสาร PDF, “มือถือ”→โทรศัพท์, “ปุ่ม”→ปุ่ม, “กราฟ”→กราฟ ใน Long ใส่ป็อปอัพให้ทุกสิ่งสำคัญที่เอ่ยถึง สะสมบนฉากได้หลายชิ้นถ้ายังอ่านทัน ชิ้นล่าสุดได้จุดเน้น
2. ใช้ badge วงกลม/การ์ดมุมมน เงานุ่มและชื่อสั้น ตำแหน่งสัมพันธ์กับภาพหลัก; เครื่องมือสองตัวอาจอยู่คนละข้างหน้าต่างเหมือนตัวอย่าง แต่แนวตั้งย้ายมาอยู่ด้านบนหรือในแผงได้
3. ป็อปเข้าใกล้คำที่เอ่ยถึง: y ขึ้นเล็กน้อยราว 24–48px และ scale 0.88→1.04→1 พร้อม opacity ที่ seek ได้ ใช้เวลา entrance ประมาณ 0.2–0.35s มี overshoot เบา ๆ ไม่เด้งหลายรอบ ค้างประมาณ 0.7–1.5s หรือตลอดประโยคที่ยังอธิบายสิ่งนั้น แล้วออกนุ่ม 0.15–0.25s ปรับตามเสียงและความซับซ้อนของภาพ
4. ถ้าสิ่งเดิมยังทำหน้าที่ในเรื่อง ให้คงอยู่และเปลี่ยนการเน้น แทนการปิด/เด้งใหม่ซ้ำ ระหว่างค้างให้มี idle motion เบา ๆ (ลอยขึ้นลง 4–8px หรือ scale 1→1.03 วนช้า 1.6–2.4s) ไม่ค้างนิ่งสนิท

โลโก้ใช้ไฟล์ที่ถูกต้องจากงานเดิม/ผู้ใช้หรือแหล่งทางการที่เข้าถึงได้ เก็บแหล่งใน project ไม่อ่าน credentials หรือเปลี่ยน sharing เพื่อหา asset ถ้ายังไม่มีใช้ป้ายชื่อกับไอคอนทั่วไป ไม่วาดเครื่องหมายเดาเอง รูปสิ่งของใช้ SVG/ภาพที่มี หรือ image-generation skill เมื่อจำเป็นต้องสร้าง bitmap ใหม่ ข้อความต้องคมระหว่าง hold และมีพื้นตัดกัน

## E. Progressive build — ประกอบภาพตามคำอธิบาย

ใช้ร่วมกับ pop-up เมื่อพูดถึงการสร้างเว็บ หน้าจอ หรือระบบ วางโครงหลักก่อน เช่นหน้าต่าง browser แบบเรียบ แล้วเพิ่มส่วนตามลำดับคำ: แถบเมนู → ส่วนหัว/ปุ่ม → การ์ด → กราฟ แต่ลำดับจริงยึดสิ่งที่พูด ไม่ล็อกลำดับนี้ทุกคลิป

หลักการประกอบทีละส่วนใช้กับหัวข้ออื่นได้: อธิบายคอมพิวเตอร์ให้เพิ่มชิ้นส่วนที่พูด อธิบายเอกสารให้เพิ่มหัวข้อ/ช่องข้อมูล อธิบายกระบวนการให้เพิ่มจุด/เส้นเชื่อม เลือกโครงตามความหมาย ไม่ย้ายตัวอย่างเว็บไปใช้กับทุกเรื่อง

แต่ละ component มี entrance ของตัวเองแล้วอยู่ต่อในตำแหน่งสุดท้าย การ์ดเลื่อนเข้าและ settle, ปุ่ม scale-pop, แท่งกราฟยืดจากฐาน ไม่มีค่าตัวเลขหรือผลธุรกิจสมมติที่ดูเหมือนข้อมูลจริง ภาพรวมค่อย ๆ สมบูรณ์แล้วค้างให้อ่านได้ ไม่วางทั้งหมดตั้งแต่ต้นแล้วกระพริบอย่างเดียว

วาง hero frame ตอนประกอบครบก่อน animation เพื่อไม่ชนกัน จัดช่วง entrance ภายในเสียงเดิม ถ้าเวลาสั้นเกินไปใช้ส่วนที่สำคัญที่สุด ไม่บังคับใส่องค์ประกอบที่ไม่ได้พูด

ภาพเว็บแบบ schematic อธิบายแนวคิดได้ แต่คำสั่งสาธิตหน้าจอ/ผลลัพธ์จริงต้องใช้ฟุตเทจจริง ไม่สร้าง screenshot สมมติที่เหมือนหลักฐาน product behavior ไม่เพิ่มป้ายอธิบายการผลิต/ประกาศยาว ๆ บนภาพเอง; ทำให้ความเป็นกราฟิกแนวคิดชัดด้วยรูปแบบภาพที่เรียบ หากบรีฟต้องมีคำกำกับ ให้ใช้ตามนั้น

## F. แนวทางจากคลิปอ้างอิง 2026-10-21 (โมชันมากขึ้น)

ต้นทาง: คลิป YouTube ที่ผู้ใช้ให้ (youtu.be/4wBVuj2an8E, Eric Tech, ~15 นาที) ศึกษาจากเฟรมทุก 12 วินาทีและเฟรมถี่ 2.5 fps บางช่วง เรียนรูปแบบการเคลื่อน ไม่คัดลอกชื่อ โลโก้ mascot หรือ avatar

ภาพรวม: พื้นเทาอุ่นเต็มเฟรม มีการ์ดขาวมุมมนใหญ่กลางจอหนึ่งใบเป็นเวที ผู้พูดกรอบเล็กมุมมนขวาล่างตลอด ฉากเปลี่ยนบ่อยราว 5–15 วินาที และแทบไม่มีช่วงนิ่ง ใช้รูปแบบต่อไปนี้ตามความหมายของคำพูด:

| รูปแบบ | ใช้เมื่อ | วิธีทำ |
|---|---|---|
| **Slot fill** | เปรียบเทียบหรือเอ่ยหลายรายการ | วางกรอบช่องว่างก่อน แล้วไอคอน+ชื่อเด้งเข้าทีละช่องตรงคำพูด (scale 0.6→1.08→1, 0.3s) |
| **Cycle highlight** | วนซ้ำ ลองแล้วพัง แก้แล้วแก้อีก | วางโหนดเป็นวง มีลูกศร แล้วกรอบส้มวิ่งวนจากโหนดหนึ่งไปอีกโหนด ~0.4s/โหนด ตลอดช่วงพูด |
| **Branch choose** | ทางเลือกสองทาง เลือกทางที่ถูก | เส้นวาดจากต้นทางถึงจุดแยก โหนดถาม (ดำ) โผล่ แล้วเส้นทางที่เลือกวาดเป็นส้มและโหนดปลายเปลี่ยนเป็นส้มทึบ ทางอื่นจางลง |
| **Cursor guide** | ชี้ว่ากำลังพูดถึงชิ้นไหน | เคอร์เซอร์จำลองเคลื่อนแบบ ease ไปที่การ์ด แล้ว click pulse (การ์ด scale 0.96→1 + วงกระเพื่อม) ใช้ในฉากกราฟิกเท่านั้น ไม่ทำให้ดูเหมือนหน้าจอจริง |
| **Pills / tabs** | ขั้นตอนหรือหมวด | แถบ pill เรียงกัน ตัวที่พูดถึงเปลี่ยนเป็นพื้นดำตัวขาว เลื่อนไปตามคำพูด |
| **Progress / meter** | สะสม เพิ่มขึ้น ใกล้เต็ม | แถบหรือช่องสี่เหลี่ยมเติมทีละช่อง ตามจังหวะคำ ไม่ใส่ตัวเลขที่ไม่มีหลักฐาน |
| **Big code / quote card** | อ้างคำสั่ง โค้ด หรือประโยคสำคัญ | การ์ดดำตัวอักษร mono ≥ 48px พิมพ์ทีละบรรทัด หรือบรรทัดที่พูดถึงขึ้นแถบส้มจาง |
| **Map pan & zoom** | ภาพรวมใหญ่ที่มีหลายส่วน | วางแผนภาพใหญ่ทั้งผืน แล้วกล้องเลื่อน/ซูมไปส่วนที่พูด 0.8–1.2s ease นุ่ม ค้างให้อ่าน แล้วไปส่วนถัดไป |
| **Blur handoff** | เปลี่ยนฉากภายในช่วงอธิบาย | ฉากเดิม blur 0→12px + จาง ขณะการ์ดเวทีเปลี่ยนขนาด (morph) เป็นฉากใหม่ 0.4–0.6s |
| **Idle life** | ระหว่างค้างภาพ | ไอคอนลอย/หายใจ ไฮไลต์วน หรือเคอร์เซอร์ขยับเล็กน้อย ไม่ให้นิ่งเกิน ~2.5s |

ทุกการเคลื่อนต้องคำนวณจากเวลา (seek ได้) ตามกติกา deterministic ของ HyperFrames ใช้กับช่วงอธิบายเท่านั้น ช่วงสอนใช้หน้าจอจริง แต่เพิ่มชีวิตได้ด้วย zoom/pan เข้าจุดที่คลิก และกรอบ/ไฮไลต์สีส้มบนหน้าจอจริง (ไม่ใช้เหลือง)

## แนวตั้งและพื้นที่ผู้พูด

สำหรับ 1080×1920 จัดโหนดบน→ล่างหรือปรับเข้าแผงใน layout เดิม แสดง 2–3 ขั้นต่อช่วงเมื่อพื้นที่แคบและปรับตัวอักษรใหม่ ไม่ครอปแนวนอนจนต้นทาง/ปลายทางหาย เว้นผู้พูด/ซับและตรวจภาพที่ย่อเทียบขนาดจอโทรศัพท์

## ตัวอย่างแปลงคำพูด

“รับข้อมูลจากฟอร์ม อีเมล และแชตมารวมไว้ที่เดียว จากนั้น AI ตรวจสอบ แล้วส่งให้ทีมอนุมัติ”

- ฉากแรก: 3 ต้นทาง → “ข้อมูลรวม”; converging paths ให้ถึงช่วง “รวมไว้ที่เดียว”
- ฉากถัดไป: “ข้อมูลรวม → AI ตรวจสอบ → รอทีมอนุมัติ”; workflow board ไม่ติดเครื่องหมายตรวจผ่านเพียงเพราะพูด “ตรวจสอบ”
- ถ้าต่อด้วย “แล้วกดปุ่มนี้” คืนหน้าจอจริงก่อน action ใช้ผลสาธิตจริงเป็นหลักฐานการอนุมัติ
