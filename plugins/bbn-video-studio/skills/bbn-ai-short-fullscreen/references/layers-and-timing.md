# ชั้นภาพและเวลา — ฮุคเต็มจอ เนื้อหาบน–ล่าง

## ขอบเขตและหลักฐาน

ใช้กติกาปัจจุบันใน SKILL.md เป็นค่าเริ่มต้น: ไดคัตเฉพาะฮุค จากนั้นกล้องจริงพร้อมห้องเดิมครึ่งล่าง โมชั่นอธิบาย/หน้าจอจริงครึ่งบนตามคำพูด ไม่ใช้ตัวอย่าง full-canvas body เก่ามาทับกฎนี้ คลิปอ้างอิงที่ไม่มี audio stream ใช้ยืนยันเฉพาะภาพ ไม่ยืนยันคำพูด/SFX/จังหวะคำ

## ชั้นฮุค

จากหลังไปหน้า: ผลงาน/highlight จริงเต็ม canvas → วิดีโอผู้พูด cutout ตรงเสียง → Name Hook → โลโก้แอป → ซับ แต่ละชิ้นเป็น editable layer แยกกัน ปรับ z-order เพื่อไม่ให้หัว/มือบังข้อความ โลโก้หนึ่งอันกลางด้านบน หรือสองอันข้างกัน ไม่เติม +/VS เอง

ใช้ hook-fullscreen.svg หรือ hook-two-apps.svg เป็น role guides ไม่ใช่งานเสร็จ เอาเส้น guide/player chrome/placeholder ออกจาก export ตำแหน่งตั้งต้น 1080×1920: โลโก้บน หัวข้อสั้นใต้โลโก้ ผู้พูดด้านล่าง เว้น safe margins และตรวจจอโทรศัพท์ ไม่ล็อกตำแหน่งจนทับผลงานจริง

## ชั้นเนื้อหาหลังฮุค

สำหรับ 1080×1920 ใช้บนประมาณ y=0–960 และล่าง y=960–1920:

- **บน:** โมชั่นแนวคิดใน topic bridge/explanation; genuine recorded screens/results เมื่อถึง look/demo cue; การ์ด Prompt/CTA ในท้ายตามเสียงจริง
- **ล่าง:** วิดีโอกล้องผู้พูดพร้อมห้องเดิม RGB ปกติ ไม่ alpha/matte และไม่ใช้ cutout ภาพนิ่ง รักษาเสียง/lip sync/หัว/มือจาก source
- **ซับ:** clock เดียวกับเสียง เว้นใบหน้า ป้ายโมชั่น ปุ่ม/ข้อความผลงาน และ platform safe areas ตรวจทุก cue จาก final encode

เมื่อจบฮุค ให้ชุดชื่อ/โลโก้ฮุคออกและเริ่มกล้องพร้อมห้องเดิมทันที ใส่ประโยคเสียงจริงครบที่บอกสิ่งที่จะสอน โมชั่นครึ่งบนช่วยอธิบายเครื่องมือ/ความสัมพันธ์ ไม่ข้าม topic bridge หรือใช้ generic B-roll ยืดช่วงอธิบาย

body-fullscreen.svg เป็นตัวอย่างเก่า ไม่ใช้กำหนดเลย์เอาต์เนื้อหาใหม่ หากช็อตเล่นผลงานจริงไม่มี narration ที่ต้องเห็นผู้พูด ใช้ result-only เต็มจอได้เพื่อไม่บังงาน จากนั้น Prompt/CTA ที่มี narration กลับบน–ล่าง

## รักษารายละเอียดภาพ

รักษาสัดส่วนทุก source ไม่ stretch คนหรือ UI ใช้ crop/pan/zoom เฉพาะจุดที่ไม่ตัดรายละเอียดจำเป็น หาก screen แนวนอนครอปแล้วปุ่ม/ผลหาย ให้ contain ภายในแผงบนพร้อม backing กลมกลืน ตรวจความอ่านออกบนมือถือ ไม่มีเหตุผลให้ redraw UI หรือแทนด้วย mock output

## Final clock และ cue

ใช้ FPS ของแผนหลักกับช่วงจำนวนเต็ม `[start_frame,end_frame)` ทุก segment ระบุ mode, source asset, source→final mapping, layout, พื้นที่ซับ/UI และสถานะว่า timing ตรวจจากเสียงแล้วหรือเป็น ASR estimate/provisional ไม่เรียกเวลาจาก transcript อย่างเดียวว่า human verified

เก็บอย่างน้อย hook_end_frame, topic_bridge start/end, explanation ranges, look/demo start, result playback ranges และ Prompt/CTA boundaries เวลา local ของกราฟิก = `(final_frame-segment_start_frame)/fps` ไม่มี clock แยกสำหรับ mask/คน/ข้อความ/โมชั่น

คำว่า 00:07 เป็นรอยต่อโดยประมาณของตัวอย่าง ไม่ใช่เวลาบังคับ เลือกจบฮุคจากประโยคครบ เมื่อเสียงชวนดูงานหรือเริ่มพาทำ ให้จบโมชั่นก่อนเฟรมของ cue และแสดงภาพจริงตั้งแต่เฟรมนั้น อย่ารอ historical segment จบ การรอโหลด/อธิบายวิธีทำใน demo ยังคงหน้าจอจริง จึงเปิดโมชั่นใหม่ได้เฉพาะ explanation ที่แยกชัด

Transition อยู่ในช่วงที่จัดสรร ไม่ยืดเสียง/เลื่อนเวลาเดิมนอกขอบเขต ช็อตผลลัพธ์ต้องมี playback หลังคำชวนดู ไม่ใช่ภาพเล็กแวบเดียวตอนเกริ่น ระยะเวลาเลือกจากการอ่าน/ดูงานจริง ไม่ล็อกความยาวจากตอนตัวอย่าง งานแก้ภาพอย่างเดียวคงเสียง ฮุค ซับ และกล้องล่างที่รับรองแล้ว พร้อมตรวจ decoded frame ordinal/stream preservation ตามขอบเขต
