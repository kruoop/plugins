# BBN AI Short — ฮุคเต็มจอ เนื้อหาบน–ล่าง

ใช้กับงาน Short ของ BBN ที่ผู้ใช้สั่ง ชื่อสกิลเดิมคงไว้เพื่อไม่ให้ workflow ขาด แต่ **ไม่ได้หมายถึงไดคัตคนหรือใช้ภาพเต็มจอตลอดคลิป** ค่าเริ่มต้นปัจจุบันคือฮุคเต็มจอพร้อมวิดีโอผู้พูด cutout → เกริ่นว่าจะสอนอะไร → เนื้อหาแบ่งบน–ล่าง → ผลงานจริง → แจก Prompt/CTA ที่มีหลักฐาน ใช้กับงานใหม่โดยไม่ถามเลือกสไตล์ซ้ำ ไม่แปลงคลิปเก่าหรือเริ่ม EP จากการอัปเดตสกิล

## Short แบบ teaser และการแก้ท้ายคลิป — 2026-10-30

เมื่อผู้ใช้ขอ Short เพื่อดึงคนไปดู Long ให้ใช้ [teaser และการแก้การ์ดท้าย](references/teaser-and-ending-revisions.md) ก่อนโครง tutorial ด้านล่าง เลือกเฉพาะประโยคจริงที่สร้างความสนใจ ไม่บังคับใส่บทสอน เดโม หรือแจก Prompt ครบทุกช่วง ยึด EP และความยาวที่ผู้ใช้แก้ล่าสุด; 45 วินาทีเป็นเป้าของงานที่ขอประมาณ 45 วิ ไม่ใช่ค่าเดียวของทุก Short

## โครงภาพตามช่วง

| ช่วง | ภาพ | ผู้พูด |
|---|---|---|
| Hook | highlight/ผลงานจริงเต็ม canvas + หัวข้อสั้น + โลโก้แอป | วิดีโอจริงตรงเสียง ตัดพื้นหลังเฉพาะฮุค |
| Topic bridge | โมชั่นครึ่งบน บอกเครื่องมือ/สิ่งที่จะสอนตามประโยคจริง | กล้องจริงพร้อมห้องเดิมครึ่งล่าง ไม่ไดคัต |
| Concept explanation | โมชั่นอธิบายครึ่งบนจาก bbn-explainer-motion | กล้องจริงพร้อมห้องเดิมครึ่งล่าง ไม่ไดคัต |
| Look cue / hands-on demo | หน้าจอหรือผลงานจริงครึ่งบน ตั้งแต่เสียงชวนดู/เริ่มพาทำ | กล้องจริงพร้อมห้องเดิมครึ่งล่าง ไม่ไดคัต |
| Result-only playback | โชว์ผลงานจริงให้เห็นชัด อนุญาตเต็มจอเมื่อไม่มี narration ที่ต้องเห็นผู้พูด | ลด/เอาผู้พูดออกเฉพาะช็อตที่บังงานตามเนื้อหา |
| Prompt / CTA | การ์ดครึ่งบน ตรงทรัพยากรและถ้อยคำที่มีจริง | กล้องจริงพร้อมห้องเดิมครึ่งล่าง ไม่ไดคัต |

เริ่มที่ 1080×1920 และ FPS ของแผนหลัก เนื้อหาหลังฮุคใช้ประมาณ 50/50: บน 1080×960 ล่าง 1080×960 รักษาสัดส่วน ไม่ยืดหน้า/UI ปรับ crop ตาม source ให้หัวคนครบ ซับไม่ทับใบหน้าและข้อมูลสำคัญ คำว่า 00:07 เป็นแนวรอยต่อของตัวอย่าง ไม่ใช่เวลาตายตัวทุก Short; จบฮุคตามประโยคจริง ความยาวทั้งคลิปยึดบรีฟและประโยคครบ ไม่บังคับทุกตอนให้เท่าตัวอย่าง

## เลือกเนื้อหาและเสียง

1. อ่าน/ดูคลิปที่จำเป็นให้ครบ ใช้ transcript ร่วมกับภาพจริงและ source→final mapping เลือกคำเปิดที่น่าสนใจจากเสียงที่อัดไว้จริง ไม่แต่งคำพูด/โคลนเสียงหรือสร้าง AI avatar
2. ถ้าฮุคผ่านแล้ว ให้คงฮุคเดิมทั้งภาพ เสียง ซับ และเวลาเมื่อแก้เฉพาะเนื้อหา ไม่เลือกฮุคใหม่เอง ใช้ bbn-tutorial-hook ช่วยเลือกคำและผลงาน ไม่นำเทมเพลตฮุคสองจอเก่ามาแทนฮุคเต็มจอ
3. หลังฮุค ใส่ **ประโยคเสียงจริงครบที่บอกว่าวันนี้สอนอะไร/ใช้เครื่องมืออะไร** ก่อนเดินเนื้อหา ห้ามข้ามจากคำขายประโยชน์ไปอธิบายศัพท์ทันที ถ้ามีหลาย take ให้เลือก take สมบูรณ์ ไม่ตัดคำจนเปลี่ยนความหมาย
4. แยก `hook`, `topic_bridge`, `explanation`, `demo`, `results`, `prompt`, `cta` จากคำพูดและ footage จริง ชื่อ segment เก่าว่า teaching ไม่พิสูจน์ว่ากำลังสาธิต หากเป็นการอธิบายแนวคิด ให้ใช้โมชั่นครึ่งบน ไม่ใช้ภาพเว็บ/ผลลัพธ์ B-roll มาค้างแทนโมชั่นเพียงเพราะเป็นภาพจริง
5. เมื่อพูดชวนดูงาน เช่น เดี๋ยวมาดูผลลัพธ์ หรือเริ่มพาทำบนจอ ให้กลับภาพจริงตรง cue นั้น ไม่รอจบช่วงที่ตั้งชื่อไว้ และไม่ปล่อยโมชั่นค้างทับ demo การอธิบายวิธีทำ/รอโหลดภายในการสาธิตยังคงหน้าจอจริง
6. หลังชวนดูต้องมีช็อตเล่น **ผลงานที่ทำเสร็จจริงจากตอนนั้น** ให้เห็นและอ่านทัน ไม่ถือว่าภาพเล็กในช่วงเกริ่นคือการโชว์งานแล้ว ไม่สร้าง mock UI/ผลงานใหม่เป็นหลักฐาน ระยะโชว์งานเลือกตามเนื้อหา ไม่ล็อกจำนวนวินาทีจาก EP ตัวอย่าง
7. หากท้ายคลิปแจก Prompt ให้ใช้เสียงที่พูดถึง Prompt จริง พร้อมการ์ดที่ระบุ Prompt และ CTA ตามบรีฟ เสนอเฉพาะทรัพยากรที่มีจริง ไม่แต่งคำเชิญ ไม่อ้างว่าระบบตอบคอมเมนต์อัตโนมัติถูกตั้งแล้ว

## ฮุคและชั้นแก้ไขได้

### งานแก้ให้เหมือน EP อ้างอิง

เมื่อเจ้าของช่องระบุว่าให้เหมือน EP ก่อนหน้า ให้เปิด MP4 ที่ส่งจริงและ compositor/caption assets ของรุ่นที่รับรองก่อนปรับ อย่าใช้สกิลทั่วไปหรือชื่อฟอนต์อย่างเดียวแทนหลักฐานสไตล์ เทียบ hook, name/logo/headline, ขนาดและตำแหน่งผู้พูด, รอยต่อกลับห้องเดิม และซับจากเฟรมจริงของทั้งสองคลิป นำ recipe การจัดวาง/ฟอนต์/สี/outline/shadow มาใช้กับเนื้อหาและแบรนด์ของตอนปัจจุบัน ไม่คัดลอกคำพูด ชื่อเครื่องมือ หรือความยาวฮุคของตอนอ้างอิง ตรวจซับใน final ครบทุก event รวมเฟรมแรก/สุดท้ายและหลายบรรทัด; รักษาเสียงและ cut plan เดิมเมื่อคำขอแก้เฉพาะภาพ

- ใช้ผลงาน/highlight จริงที่ตรงเรื่อง ไม่เอาหน้าเริ่มต้นแอปหรือภาพ generate มายืนยันผลสำเร็จ
- Name Hook สั้นประมาณ 1–2 บรรทัด ไม่เคลมเกินคลิป วางโลโก้ หัวข้อ ซับ และผู้พูดเป็นชั้นแยกที่แก้ไขได้ เอาชุดฮุคออกเมื่อจบฮุค
- หนึ่งแอปใช้โลโก้จริงหนึ่งอัน สองแอปวางข้างกัน ไม่เติม +/VS เว้นแต่บรีฟขอ ใช้แอปของตอนนั้น ไม่ยกแบรนด์ตัวอย่างเป็นค่าเริ่มต้น
- Cutout ต้องเป็นวิดีโอที่เคลื่อนไหวและตรงเสียง ไม่ใช้ภาพนิ่งเลื่อนแทนคนพูด ทำ matting เฉพาะช่วงฮุคและ reuse ส่วนที่รับรองแล้ว

## ประกอบและตรวจงาน

อ่าน [ชั้นภาพและจังหวะ](references/layers-and-timing.md) ก่อนประกอบ และ [ตัดพื้นหลังวิดีโอและตรวจงาน](references/video-cutout-and-qa.md) สำหรับฮุคและ encoded QA ใช้เครื่องมือ/runtime/fonts/models ที่ตรวจว่ามีบน host ปัจจุบัน พาธ panda ใน provenance ไม่ใช่หลักฐานว่าติดตั้ง ไม่ติดตั้ง engine ใหม่หรือส่ง private footage ขึ้น cloud โดยพลการ

ใช้ clock เดียวกันและช่วงจำนวนเต็ม `[start_frame,end_frame)` สำหรับกล้อง หน้าจอ เสียง ซับ mask และโมชั่น เก็บ cut plan/cue/editable source/provenance ในโฟลเดอร์ EP งานแก้ภาพอย่างเดียวรักษาเสียงและเวลาเดิม ใช้ deterministic seek/render เมื่อทำ HTML/SVG/GSAP ไม่ remaster เสียงหรือเริ่ม ASR ใหม่ทั้งเรื่องโดยไม่จำเป็น

ตรวจจาก MP4 ที่ encode จริง:

- ฮุค: ผู้พูดเคลื่อนไหว ลิปซิงก์ ขอบผม/มือ/หน้าไม่หาย ชื่อและโลโก้อ่านทัน ไม่เปลี่ยนฮุคที่ผ่านแล้ว
- รอยต่อ: ประโยคแนะนำสิ่งที่จะสอนครบ คนกลับเป็นกล้องพร้อมห้องเดิมตั้งแต่เฟรมแรกหลังฮุค
- เนื้อหา: โมชั่นครึ่งบนตรงความหมายและคำสำคัญ หน้าจอจริงกลับตรง look/demo cue ไม่ถูกแทนด้วย generic B-roll หรือกราฟิกระหว่างสาธิต
- ผลงานและท้ายคลิป: มี playback จริงหลังคำชวนดู ข้อมูลสำคัญไม่ถูกบัง ท้ายแจก Prompt ตรงเสียงจริง คนใน Prompt/CTA ไม่ถูกไดคัต
- ทุกช่วง: ตรวจทุก caption event/หลายบรรทัด รอยต่อและ privacy เทียบ source กับภาพ final ตรวจ resolution/FPS/frame count/duration/full decode และเสียง บันทึกการฟังจริงแยกจาก ASR/การตรวจ waveform ไม่อ้างว่าฟังทั้งคลิปเมื่อไม่ได้ทำ

## ขอบเขตและส่งงาน

ทำเฉพาะ Short/สกิลที่สั่ง ไม่แก้ Long, Package, ปก หรือ Short ที่รับรองแล้วนอกขอบเขต ไม่ลบไฟล์จากคำขออัปเดตสกิล ส่ง MP4 ที่ประกอบและตรวจจริง พร้อมซอร์ส/cue ตามบรีฟ ใช้ workflow ส่ง review file เดิมเมื่อได้รับอนุญาต ไม่เผยแพร่/ตั้งเวลา/สร้าง platform draft เอง

หากไม่มีเครื่องมือ matting หรือ source ที่จำเป็น ให้บอกสิ่งที่ขาด ไม่ส่งภาพนิ่งแทน cutout hook หรือขยายข้อจำกัดของฮุคไปเปลี่ยนเลย์เอาต์เนื้อหา SVG `body-fullscreen.svg` เป็นตัวอย่างเก่าของ full-canvas body ไม่ใช่เทมเพลตปัจจุบัน ใช้ role guides ของฮุคเฉพาะบทบาทและลบ placeholder ก่อนส่ง
