# เนื้อหา จังหวะ และการส่งงาน

## หาแกนฮุค

อ่านบท/เสียงและดูสิ่งที่สอนจริง แล้วตอบให้ได้: ผู้ชมจะทำอะไรสำเร็จ สิ่งที่เปิดโชว์คือไฟล์ใด ใครพูด ใช้แอปอะไร และแอปสัมพันธ์กันอย่างไร ใช้คำตอบนี้สร้าง Name Hook และเลือกภาพบน ไม่เริ่มจากโลโก้/ชื่อฮุคของตัวอย่างเก่า

Name Hook เป็นหัวข้อบนภาพ สั้นและเฉพาะผลลัพธ์ อาจใช้ “ทำ [ผลงาน] ด้วย [แอป]”, “[ผลลัพธ์] จาก [ต้นทาง]”, หรือ “[A] vs [B]: [โจทย์ที่เทียบ]” แต่เลือกถ้อยคำจริงที่อ่านง่ายและซื่อสัตย์ ป้ายชื่อบนปกไม่จำเป็นต้องตรงทุกคำกับประโยคพูด

ตัวอย่าง:

- สอนสร้าง MV ด้วยหนึ่งแอป → “สร้าง MV ง่าย / ด้วย [แอป]” เมื่อเนื้อหาสนับสนุนว่าง่าย
- ใช้ CapCut ตัดคลิปและ Canva ทำปก → “ทำคลิป / พร้อมปก” กับโลโก้ CapCut + Canva
- เทียบสองแอปในงานเดียว → “ทำ [งานเดียวกัน] / ตัวไหนเหมาะ?” กับ A VS B; ไม่ใช้คำว่า “ชนะขาด” หากไม่มีหลักฐาน

ถ้ามีฮุคที่ผู้พูดอัดไว้แล้ว ใช้ take นั้นและตัดให้กระชับโดยรักษาประโยคสมบูรณ์ หากขอเขียนฮุคใหม่ ให้เขียนให้เห็นผลงาน/ประโยชน์และมีทางเข้าสอน ไม่อ้างว่าบทนั้นมีเสียงแล้ว ไม่สร้างเสียงโคลนหรือ AI presenter เพิ่มเอง ถ้าไม่มี take ที่รองรับบทใหม่ ให้ส่งบทที่พร้อมอัดหรือขอเฉพาะข้อมูลที่จำเป็น ไม่แสร้งว่าตัดวิดีโอพร้อมแล้ว

## เลือก final output/highlight

เลือกช็อตผลงานที่ดีที่สุดจากตอนปัจจุบัน ใช้ผลลัพธ์ที่ผู้ชมจะเห็นจากวิธีที่สอนจริง ตรวจแหล่งและสัมพันธ์กับบท ไม่เอาภาพจากตอนอื่นหรือภาพ generate มาทำเป็นหลักฐานสำเร็จ

ถ้ามีหลายผลงาน เลือกจุดเด่นน้อยช็อตที่ดูออกทันที ไม่ montage เร็วจนผู้ชมไม่เข้าใจ หากยังไม่มีผลงาน ให้หาในโฟลเดอร์/ตอนที่ได้รับอนุญาตก่อน กรณีหาไม่ได้ ให้แจ้งว่าขาด final-output asset และทำส่วนบท/โครงต่อได้ แต่ไม่ยกระดับหน้าเริ่มต้นแอปให้เป็นผลงานสำเร็จ

โลโก้ใช้ asset ถูกต้องของแอปที่เรียนจริง แหล่งคือผู้ใช้/โฟลเดอร์งาน/แหล่งทางการที่เข้าถึงได้ ไม่ redraw โลโก้เดาเอง หากยังไม่มีและทำ draft อยู่ ใช้ชื่อแอปเพื่อวางตำแหน่งและแจ้งว่ายังไม่ใช่ปกสมบูรณ์ตามเทมเพลตโลโก้ เก็บ provenance ใน project ไม่เปิดเผย credentials

## เวลาและรอยต่อเข้าสอน

ใช้เวลา final หลังตัดและ FPS ของ editor หลัก แยกช่วง `[hook_start_frame,teaching_start_frame)` กับ teaching ต่อมา ช่วง hook มี entrance/hold/exit ภายในช่วงที่จัดสรร ความยาวยึดประโยคฮุคและการอ่านภาพ ไม่ใช้ความยาวตัวอย่างเป็นข้อบังคับ

ผูกผลลัพธ์กับคำบอกประโยชน์ Name Hook ค้างให้อ่านทัน โลโก้และหัวข้ออาจเข้าแบบ pop/slide สั้น ๆ ราว 0.2–0.4s เป็นค่าลอง ไม่ต้องเลื่อนทุกองค์ประกอบตลอดเวลา ใช้การเคลื่อนที่ช่วยอ่านและไม่ปิดผลลัพธ์

จบฮุคตามประโยคครบ ไม่บังคับเวลาประมาณ 00:07 ของตัวอย่าง สำหรับ Short auto-post-content ให้ชุดชื่อ/โลโก้ฮุคออกและคืนผู้พูดกล้องจริงพร้อมห้องเดิมครึ่งล่างทันทีหลังฮุค ไม่ไดคัต ใส่ประโยคเสียงจริงครบที่บอกว่าวันนี้สอนอะไร ก่อนเนื้อหา โมชั่นครึ่งบนใช้กับ topic bridge/แนวคิด เมื่อถึงคำชวนดูงานหรือเริ่มพาทำ ให้หน้าจอ/ผลงานจริงกลับตั้งแต่เฟรมนั้น ใช้คำพูดและ footage หา cue ไม่รอ segment เก่าจบ รักษาผลงานจริงและท้ายแจก Prompt ตามที่ขอ ซับ/เสียงคงตามงานหลัก เทมเพลต split hook ใช้เมื่อบรีฟขอโดยตรงเท่านั้น

ช่วงกด/พิมพ์/รอโหลดหรืออธิบายวิธีทำภายในการสอนยังเป็น teaching ใช้หน้าจอจริงตลอด ไม่แทรกโมชั่นอธิบายแทนหน้าจอ หากมี explanation segment แยกต่างหากภายหลัง จึงใช้ bbn-explainer-motion เมื่อบรีฟต้องการ

ข้อมูล cue อย่างน้อย: topic, Name Hook, app names, relationship `single/combine/compare`, result asset, speaker take, portrait source, FPS, hook start/end frames, teaching start frame, logo sources, เวลา headline/transition, และสถานะจังหวะว่าเป็น provisional หรือเช็กเสียงแล้ว ไม่มีเสียงจริงไม่กำหนดเฟรมคำว่า verified

## เสียง ผู้สอน และเครื่องมือ

เสียงผู้พูดเป็นหลัก ถ้าคลิปผลลัพธ์มีเสียงที่ต้องโชว์ เช่น MV ให้จัดจังหวะฟังสั้น ๆ ตามบรีฟหรือ duck ใต้เสียงพูด ไม่เปิดสองเสียงชนกัน งานภาพอย่างเดียวรักษา mastered audio เดิม งานตัดฮุคใหม่รักษาซิงก์และคำครบ ใช้เพลง/SFX เมื่อ workflow ของงานอนุญาตอยู่แล้ว ไม่เพิ่มเพลงหรือเสียงใหม่เพราะเทมเพลตดูคึกคักเพียงอย่างเดียว

สำหรับปกตัดพื้นหลังภาพผู้สอนด้วยเครื่องมือ image editing ที่มี ถ้ามี transparent cutout ที่รับรองแล้วให้ reuse ตรวจขอบผม/ใบหู/ไหล่บนพื้นสว่างและมืด ใบหน้าและสีผิวต้องตรงต้นทาง เปลี่ยนเฉพาะ crop/ขนาด/พื้นหลังที่บรีฟขอ ไม่เปลี่ยนคนหรือทำหน้าขึ้นใหม่

การทำฮุคใน editor ปัจจุบันไม่ต้องติดตั้ง renderer เพิ่ม ทำชั้นผลงาน/ผู้พูด/ข้อความตามเลย์เอาต์ที่บรีฟหรือ bbn-ai-short-fullscreen กำหนดบน clock เดียวกัน ถ้าใช้ HyperFrames อ่านสกิล authoring/CLI ที่มีและรักษา seekable timeline contract การแก้ปกใช้ imagegen พร้อม asset roles: layout guide, presenter identity, result, logo A/B การสร้างสกิลนี้ไม่ได้อนุญาตบริการภายนอก/อัปโหลดเผยแพร่อัตโนมัติ

## ตรวจและส่ง

- **Hook:** ดูไฟล์ encode จริงตั้งแต่ต้น ภาพบนคือผลงานที่เลือก ผู้พูดล่างตรงเสียง หัวข้อ/โลโก้อ่านทัน ไม่มี browser chrome/player controls/selection handles ที่ติดจาก screen recording หากสอน browser/UI ที่แถบเหล่านั้นจำเป็นจึงคงไว้เฉพาะบริบทการสอน
- **Cover:** ตรวจ Name Hook สะกดไทยครบ จำนวน/ตัวตนโลโก้และ +/VS ถูก ผู้สอน cutout ใหญ่ไม่บังชื่อ hook ไม่มี label PLACEHOLDER/NAME HOOK/LOGO Learning/Speaker ค้างอยู่ และภาพอ่านได้เมื่อย่อบนมือถือ
- **Handoff:** ดูรอยต่อก่อน/หลัง teaching_start_frame ผู้พูดและเสียงไม่ข้ามคำ หน้าจอจริงกลับทันเริ่มสอน ไม่มีชุดฮุคค้างบังการสาธิต
- **ไฟล์:** ตรวจขนาดจริง อัตราส่วน FPS จำนวนเฟรม และ decode วิดีโอจนจบ ใช้ 1080×1920 เป็นจุดเริ่มต้นแนวตั้งแต่รายงานขนาดที่ export ได้จริง ปกส่ง PNG/JPG ที่ตรวจแล้ว

เมื่อขอชุดฮุค ส่ง hook MP4 หรือคลิปที่ประกอบฮุคแล้วตามบรีฟ, cover ที่เลือกหนึ่งแบบหรือตามจำนวนที่ขอ, Name Hook ที่ใช้, composition/project และ cue record เมื่อขอเฉพาะข้อความ/ปก/ฮุคให้ทำตามขอบเขตนั้น ไม่เพิ่มจำนวนปกเป็นสามตามค่าเริ่มต้นของสกิลแนวนอนอื่น ไม่เผยแพร่เอง
